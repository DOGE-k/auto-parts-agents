# 汽车零部件工厂四智能体协作平台

面向汽车零部件生产协同场景的业务协作平台。报价、采购、跟单和质量四个智能体连接本机运行的 ERPNext 与 OpenMES，帮助使用者从询价、缺料分析走到生产跟单和发运条件检查。

**第一次了解项目，请先看[项目说明](docs/项目说明.md)；第一次安装，请按[部署指南](docs/部署指南.md)操作。**

## 这个项目能做什么

| 业务环节 | 主要功能 |
|---|---|
| 报价 | 读取 BOM、价格和库存，分析成本、毛利和交期依据 |
| 采购 | 计算原材料缺口，比较供应商价格与交期，起草采购方案 |
| 生产跟单 | 关联订单和工单，查询进度，依据实际报工推算完成时间 |
| 质量 | 登记与处理质量问题，展示质量待办，检查发运条件 |
| AI 协同问答 | 用自然语言查询业务对象，展示智能体调用过程和数据依据 |
| 审批与审计 | 人工审批后写回 ERP/MES，回读结果，并保留记录 |

ERPNext 管理订单、物料、BOM、价格和库存；OpenMES 管理工单、报工和质量；本应用把跨系统分析和操作放到同一个界面。发运检查提供判定，实际发运仍由业务人员在交付环节执行。

“真实连接”表示确实访问 ERPNext/OpenMES 的接口。安装时导入的 `TEST_` / `DEMO_` 记录仍然是测试数据。真实模式下缺数据或连接失败会明确报错；真实系统写入必须经过人工审批、写回、回读验证和防重复处理。

## 系统组成和地址

```text
浏览器 5173（React + Vite）
       │
后端 9000（FastAPI：智能体协调、审批和业务留痕）
       ├── ERPNext 8080（订单、BOM、价格、库存）
       ├── OpenMES 80（工单、报工、质量）
       ├── SQLite（默认留痕库；可选 PostgreSQL）
       └── DeepSeek（AI 协同问答）
```

| 页面或服务 | 默认地址 | 用途 |
|---|---|---|
| 本项目操作界面 | [http://127.0.0.1:5173/](http://127.0.0.1:5173/) | 使用者和审阅者主要使用的页面 |
| ERPNext | [http://127.0.0.1:8080/](http://127.0.0.1:8080/) | 建站、生成凭据、维护 ERP 数据 |
| OpenMES | [http://127.0.0.1/](http://127.0.0.1/) | 管理员登录、创建产线、维护 MES 数据 |
| 本项目后端健康检查 | [http://127.0.0.1:9000/api/health](http://127.0.0.1:9000/api/health) | 排查后端是否响应 |

这些地址访问的是当前电脑。其他使用者在自己电脑打开 `127.0.0.1` 时，不会访问你的数据库。

## 第一次安装和日常启动

### 第一次安装

准备 Docker Desktop（Linux 容器模式、Compose v2）、Git、Python **3.12 或 3.13**、Node.js **20+** 和 npm。仓库不携带第三方服务源码、本机配置或依赖目录，下载代码后还不能直接双击启动。

从[部署指南](docs/部署指南.md)开始，依次完成：

1. 获取项目，运行环境准备脚本；
2. 填写 OpenMES 管理员密码和 ERPNext 数据库密码；
3. 创建 ERPNext `localhost` 站点，配置 ERP/MES 凭据；
4. 在 OpenMES 创建 `DEMO_LINE_01` 产线，导入测试数据；
5. 安装前端依赖；
6. 启动应用，检查页面和业务查询。

指南提供每一步的完整命令和预期结果。首次拉取镜像需要时间，人工配置也不会被启动按钮代替。

### 已完成配置后的日常启动

先启动 Docker Desktop，然后双击仓库根目录的 **`启动应用.bat`**。也可以在仓库根目录的 PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_app.ps1
```

脚本尝试恢复外部服务、启动后端和前端，并显示检查结果。命令行方式完成后自行打开 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)；双击启动文件会在成功后打开浏览器。

页面中进入 **系统连接 → 项目账号**，使用根目录 `.env` 中 `PROJECT_AUTH_USERNAME` 和 `PROJECT_AUTH_PASSWORD` 登录。这个账号用于识别操作人、审批和受控写入；ERPNext/OpenMES 的账号、API Key 和 Bearer 令牌由后端服务读取，用于连接外部系统，不需要在页面中分别登录。普通写入不需要填写高级联调令牌；`REAL_WRITE_API_TOKEN` 由部署配置在后端环境中，高级联调只用于维护人员排查认证和接口问题。

双击 **`关闭应用.bat`** 可停止本项目的前后端及相关容器，保留容器数据。请为本项目保留 9000 和 5173 端口，避免启停脚本误操作使用这些端口的其他程序。

## 当前使用边界

- 本项目尚未完成生产部署验收，当前说明针对本地验证和内部验收。
- 不支持上游没有提供接口的 SN 级追溯、订单级质量放行及实际发运执行。
- 基础种子不保证准备好所有检验记录、工艺模板和历史报工。新电脑出现“数据不足”时，按对应业务前置条件补齐。
- 当前已有本地运行记录与使用者部署反馈；全新 Windows 环境的完整复现记录仍需补齐，不能宣称“任何电脑无前置一键完成”。
- 密码、Token、API Secret 和数据库保留在各自电脑；提交代码或分享截图前检查这些内容。

测试方法、CI 和详细验证记录统一放在[开发维护](docs/开发维护.md)，避免部署说明和开发记录混在一起。

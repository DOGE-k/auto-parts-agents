## 0b. 再看运行中的 Leader 进程里到底有没有密钥

当前 shell 干净不代表 14:08 启动的那个进程干净。这条命令直接读 `/proc/<pid>/environ`，
只输出长度和 ASCII 判定，**不打印密钥**：

```bash
cd /home/ubuntu/apps/auto-parts-agents
.venv/bin/python - <<'PY'
import json
from pathlib import Path
rec = json.loads(Path("backend/data/wutong-runtime/pids/leader.json").read_text())
pid = rec["pid"]
raw = Path(f"/proc/{pid}/environ").read_bytes()
for item in raw.split(b"\0"):
    if item.startswith(b"DEEPSEEK_API_KEY="):
        value = item.split(b"=", 1)[1]
        print("进程环境中【存在】DEEPSEEK_API_KEY")
        print("  长度:", len(value))
        print("  是否ASCII:", value.isascii())
        print("  首个非ASCII位置:", next((i for i, c in enumerate(value) if c > 127), None))
        break
else:
    print("进程环境中【没有】DEEPSEEK_API_KEY（说明密钥只来自 .env）")
PY
```

判读：

| 输出 | 含义 |
|---|---|
| 存在 + `是否ASCII: False` | **根因确认**：进程用的是 shell 里那份旧密钥，`.env` 根本没被采用 |
| 存在 + `是否ASCII: True` | 进程用的是另一份 ASCII 密钥，需要重启让它改用 `.env` |
| 不存在 | 密钥来自 `.env`，那就不是密钥问题，走第 5 步的 v2 诊断 |

注意：`/proc/<pid>/environ` 只记录 exec 时的环境块，python-dotenv 之后写进
`os.environ` 的值**不会**出现在这里。所以「不存在」= 密钥来自 `.env`，这是好事。

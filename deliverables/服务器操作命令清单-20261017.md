已经确认的事实：

| 事实 | 来源 |
|---|---|
| `.env` 里的密钥是 ASCII、长度 35、`sk-` 开头 | 你跑 `diagnose_deepseek_key.py` |
| 该密钥 `--live` 请求返回 HTTP 200 | 同上 |

| 五个接入进程启动于 **14:08:43**（晚于 .env 修改） | 诊断第 3 节 |
| 14:32 的技能失败栈停在 `httpx/_models.py:156 __init__` 的 `_normalize_header_value` | 诊断第 4 节 |

**关键推理（两条时间戳就够了）：**

- `.env` 修改时间 **01:25:04**，进程启动 **14:08:43** —— `.env` 比进程**早 12 小时**，
  说明进程启动时读到的就是文件里那个 ASCII 密钥；
- 可 14:32 的请求仍然崩在「编码请求头」，而 httpx 这一层唯一的变量头就是
  `Authorization: Bearer <key>`（`_normalize_header_value` 只做 `value.encode("ascii")`）。

两条合起来只能得出一个结论：**进程实际用的密钥不是 `.env` 里那个**。
代码里是 `load_dotenv(..., override=False)`，**启动时 shell 里已存在的同名环境变量优先**，
所以只要当时那个 SSH 会话 export 过含中文的旧密钥，`.env` 改得再对也不会生效。
而 `diagnose_deepseek_key.py` 只读文件，永远看不到这一层——这就是它显示"密钥正常"却仍失败的原因。

第 1 步就是验证这个结论的决定性命令；第 6 步会让进程自己把来源打印出来。

## 0. 决定性检查：直接看正在运行的 Leader 进程用了什么密钥

当前 shell 干净不代表 14:08 启动的那个进程干净。这条命令直接读 `/proc/<pid>/environ`，
只输出长度和 ASCII 判定，**不打印密钥**：

```bash
cd /home/ubuntu/apps/auto-parts-agents
.venv/bin/python - <<'PY'
import json
from pathlib import Path
rec = json.loads(Path("backend/data/wutong-runtime/pids/leader.json").read_text())
pid = rec["pid"]
raw = Path(f"/proc/{pid}/environ").read_bytes()
for item in raw.split(b"\0"):
    if item.startswith(b"DEEPSEEK_API_KEY="):
        value = item.split(b"=", 1)[1]
        print("进程环境中【存在】DEEPSEEK_API_KEY")
        print("  长度:", len(value))
        print("  是否ASCII:", value.isascii())
        print("  首个非ASCII位置:", next((i for i, c in enumerate(value) if c > 127), None))
        break
else:
    print("进程环境中【没有】DEEPSEEK_API_KEY（说明密钥只来自 .env）")
PY
```

判读：

| 输出 | 含义 |
|---|---|
| 存在 + `是否ASCII: False` | **根因确认**：进程用的是 shell 里那份旧密钥，`.env` 根本没被采用 |
| 存在 + `是否ASCII: True` | 进程用的是另一份 ASCII 密钥，需要重启让它改用 `.env` |
| 不存在 | 密钥来自 `.env`，那就不是密钥问题，走第 5 步的 v2 诊断 |

注意：`/proc/<pid>/environ` 只记录 exec 时的环境块，python-dotenv 之后写进
`os.environ` 的值**不会**出现在这里。所以「不存在」= 密钥来自 `.env`，这是好事。

## 6. 立刻看启动日志里新增的那行判定（这是这次修复的核心）

```bash
head -n 40 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/leader.log
```

找这一行：

```
[配置] DeepSeek 密钥判定: {"configured": true, "length": 35, "ascii": true, "firstNonAsciiPosition": null, "source": "dotenv"}
```

| `source` 值 | 含义 | 处理 |
|---|---|---|
| `dotenv` | 密钥来自 `.env`，即文件里那个 | 正常，可复测 |
| `shellEnvironment` | 来自启动时的 shell，**覆盖了 .env** | 说明还没清干净，重做第 1、2 步 |
| `ascii: false` | 运行时的密钥仍含非 ASCII | 看 `firstNonAsciiPosition`，按第 2 步清理来源 |

现在代码在 `ascii: false` 时会**直接拒绝启动**并写明来源，不会再出现「进程起来了但一调用就失败」。

## 5. 服务器：取真实失败原因（密钥已确认可用，跳过密钥排查）

你已经在服务器上跑过 `diagnose_deepseek_key.py --live`：密钥 ASCII、长度 35、`[live] HTTP 200`，
说明**密钥这条假设排除了**。接下来换成完整失败诊断，一次看到代码版本、进程是否在用旧密钥、
最近一次技能失败的真实 Traceback 和 ERP/MES 连通性。

先在 Windows 窗口 A 上传（窗口 B 保持登录状态）：

```powershell
scp "E:\competition\汽车零部件工厂智能体开发\deliverables\diagnose_wutong_failure.py" ubuntu@129.204.33.138:/home/ubuntu/diagnose_wutong_failure.py
```

回到窗口 B 执行：

```bash
cd /home/ubuntu/apps/auto-parts-agents
.venv/bin/python /home/ubuntu/diagnose_wutong_failure.py --root /home/ubuntu/apps/auto-parts-agents
```

把整份输出发我（脚本已自动脱敏，不含密钥）。同时对照三处：

- **第 3 节**：若出现 `与 .env 一致=False` 或 `.env 在该进程启动之后被修改过`，
  说明进程内还是旧密钥 —— 直接做第 8 节的 stop/start 重启，通常就能恢复；
- **第 4 节**：最后一次 `AIP 技能失败` 后面那几行 Traceback 的异常类型就是真实根因；
- **第 5 节**：ERPNext 8080 或 OpenMES 80 显示失败，说明是业务系统连不上，不是密钥问题。

## 6. 服务器：替换密钥（仅当第 5 步重新显示密钥异常时才做）

要改的文件是 `/home/ubuntu/apps/auto-parts-agents/.env`，要改的变量名是 `DEEPSEEK_API_KEY`。

```bash
cd /home/ubuntu/apps/auto-parts-agents
grep -n '^DEEPSEEK_API_KEY=' .env
```

用 nano 编辑（`Ctrl+O` 保存、回车确认、`Ctrl+X` 退出）：

```bash
nano .env
```

把 `DEEPSEEK_API_KEY=` 这一行整行替换成平台下发的密钥，形如：

```
DEEPSEEK_API_KEY=sk-这里换成真实密钥
```

要求：英文半角、`sk-` 开头、**不要加引号**、行尾不要有空格、不要写中文注释。

改完再验证一次，必须是 `is_ascii: True` 且 `--live` 显示 `HTTP 200`：

```bash
.venv/bin/python /home/ubuntu/diagnose_deepseek_key.py --root /home/ubuntu/apps/auto-parts-agents --live
```

## 7. 服务器：同步代码（二选一）

### 方案 A：服务器能访问 GitHub

```bash
cd /home/ubuntu/apps/auto-parts-agents
git pull --ff-only
git log -1 --oneline
```

### 方案 B：用刚上传的离线包（推荐，不依赖 GitHub）

```bash
cd /home/ubuntu/apps/auto-parts-agents
git fetch /home/ubuntu/wutong-update-20261017.bundle main
git merge --ff-only FETCH_HEAD
git log -1 --oneline
```

两种方案执行完后，用下面两条命令核对是否已拿到最新代码（两个哈希必须完全一样）：

```bash
git rev-parse HEAD
git bundle list-heads /home/ubuntu/wutong-update-20261017.bundle
```

第一行是当前提交，第二行会输出 `<同一个哈希> refs/heads/main`。一致即同步成功；
不一致说明上传的 bundle 不是最新版，回到第 2 步重新执行第二个 scp。

## 9. 回到叮当复测

在叮当工作助手用同一个 Leader AIC 再发一句：

```
继续核对 ERP 销售订单与 MES 工单的关联及生产进度
```

判定标准：

- 节点不再是「失败」，能看到业务正文或明确的缺数据说明 → 成功。
- 仍然失败，但失败文案现在会带原因，形如
  `技能执行失败，请检查服务日志（UnicodeEncodeError: ...）` 或
  `（IntegrationError: ...）` → 把括号里那句发我，就能直接定位，不用再翻日志。

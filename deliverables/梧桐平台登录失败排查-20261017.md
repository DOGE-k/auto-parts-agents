# 梧桐平台登录失败排查（2026-10-17 17:10）

## 结论：平台没崩，是你的账号密码不匹配

我在这台机器上对梧桐平台做了一组**只读**探测，全部用的是假账号（不会影响你的账号）：

| 探测 | 结果 | 说明 |
|---|---|---|
| `https://wt.ioa.pub/` | HTTP 200，125932 字节 | 前端页面正常 |
| `https://wt.ioa.pub/docs.html` | HTTP 200 | 文档页正常 |
| `/registry-server/openapi.json` | HTTP 200，67 个接口 | 后端正常 |
| 登录接口连续 3 次错账号 | 401、401、401，**没有 429** | 没有被限流 |
| `/api/v1/auth/verify-code` | HTTP 200，返回验证码 | 账号体系、短信/验证码链路活着 |
| `/api/v1/auth/register` | HTTP 400（校验输入） | 注册接口可用 |
| 服务器时间 | `Sat, 17 Oct 2026 09:09:16 GMT` 与本机 UTC 一致 | 没有时钟漂移 |

**关键证据**——我用不存在的用户名和你的用户名分别试了一次（密码都是明显错误的探测值）：

```
[__probe_control_20261017__] 401 {"error_name":"USER_NOT_FOUND","detail":"User not found"}
[DOGE]                        401 {"error_name":"INVALID_CREDENTIALS","detail":"Incorrect username or password"}
[doge]                        401 {"error_name":"USER_NOT_FOUND","detail":"User not found"}
```

两种错误在平台后端是**不同分支**（`registry-server/app/account/service_auth.py` 的
`authenticate_user`）：

| 分支 | 条件 | 平台返回 |
|---|---|---|
| 用户不存在 | `get_user_by_username_async` 查不到 | `USER_NOT_FOUND` |
| 用户被停用 / 没有密码 / 密码不对 | `is_active=False`、`hashed_password` 为空、`verify_password` 失败 | `INVALID_CREDENTIALS` |

你的 `DOGE` 命中的是 **`INVALID_CREDENTIALS`**，说明：

1. **账号存在且是 active 的**（否则会是别的分支）；
2. 用户名大小写正确（`doge` 直接是 USER_NOT_FOUND，说明平台区分大小写）；
3. **不匹配的是密码**。

页面上的「用户名或密码错误」就是这条 `INVALID_CREDENTIALS` 的中文提示。

## 为什么会这样

我没有、也不可能修改梧桐平台的账号或密码——本项目所有平台操作（注册、审核、EAB、证书）
都由你在平台上完成，仓库里只有公开的 ACS 资料和证书路径，没有任何账号凭据。
所以密码不匹配只可能来自这几种情况：

1. **密码记错/输入有误**：最常见。检查大小写、输入法（全角/半角）、首尾空格、
   是否多打了一个字符。密码框是掩码，很容易在切换输入法后输入中文标点。
2. **浏览器自动填充了旧密码**：Chrome/Edge 保存过早期密码时，登录框会自动填旧的。
   先清空密码框手动重输，或用无痕窗口。
3. **曾经用手机验证码注册、没设过密码**：这种情况 `hashed_password` 为空，
   平台同样返回 `INVALID_CREDENTIALS`。用「手机号 + 验证码」登录即可。
4. **近期改过密码**，或管理员重置过。

## 怎么办（按顺序）

### 1. 先确认是不是输入问题

- 用**无痕窗口**打开 <https://wt.ioa.pub/>，避免浏览器自动填充旧密码；
- 用户名填 `DOGE`（大写，平台区分大小写）；
- 密码手动输入，确认输入法是英文半角；
- 页面上「忘记密码？」可以用手机验证码重置。

### 2. 如果是手机号注册的账号

页面有「手机号登录」入口；验证码接口实测可用（我刚探测返回了 200 和验证码）。
用注册时的手机号 + 验证码登录。

### 3. 重置密码

点登录框下方「忘记密码？」，走验证码重置。如果收不到短信，
按平台文档联系管理员（页面底部通常有联系方式）。

### 4. 如果重置也失败

把页面上的**完整报错文字**（包括状态码或提示编号，不要发密码）发我，
我可以按平台返回的错误码判断是 `USER_NOT_FOUND`、`INACTIVE_USER` 还是 `INVALID_CREDENTIALS`。

## 这件事对当前进度有影响吗

**没有。** 叮当那边的修复不依赖你登录梧桐网页：

- 五个接入进程已经在服务器上跑起来，本机 mTLS 检查全部通过；
- 平台侧 ACS 早已批准，端点信息不需要重新登录修改；
- 你只需要回叮当发一句业务问题验证修复效果。

只有两种情况才需要梧桐网页登录：修改已通过的 ACS 记录、或为新角色办理注册。
这两件当前都不是阻塞项。

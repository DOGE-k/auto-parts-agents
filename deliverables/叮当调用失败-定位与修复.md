# 叮当调用失败：定位结论与修复步骤（2026-10-17）

## 一句话结论

叮当到服务器的**通道是通的**，失败发生在服务器上的**智能体进程内部**：项目代码把任何技能异常统一包装成
`技能执行失败，请检查服务日志`，而服务器上真正的异常是 `DEEPSEEK_API_KEY` 含非 ASCII 字符，
`httpx` 在编码请求头时抛 `UnicodeEncodeError: 'ascii' codec can't encode characters in position 7-9`。
Leader 和四个 Partner 读的是同一份 `.env`，所以**任何被调用的节点都会以完全相同的方式失败**——
这和截图里「生产跟单、报价两个节点失败，其余节点正常」完全一致。

## 为什么只看到「技能执行失败，请检查服务日志」

`backend/app/aip/aip_agent_service.py` 的 `_execute_skill` 捕获所有异常后只写一行日志，
对平台只回一句固定文案。所以截图里的失败信息**不含真实原因**，必须去服务器看日志：

```bash

tail -n 120 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/tracking.log
```

重点找 `UnicodeEncodeError`、`IntegrationNotConfigured`、`KeyError`、`IntegrationError`。

## 如果换密钥后仍失败

按下面顺序排查，每一步都有明确特征：

1. **只有 Partner 失败、Leader 正常** → 看 `quotation.log`/`tracking.log` 的具体异常；
   常见是 `KeyError`（技能必填参数没给）或 ERP/MES 连接失败（`IntegrationError`）。
2. **报 `unknown skill`** → 叮当按 ACS 声明的技能 ID 调用，但运行进程里该技能被
   `restrict_skills` 裁掉。检查 `build_capability_catalog` 的 `rejections`。
3. **报 `Caller AIC is not allowed`** → `runtime.json` 的 `allowedCallerAics` 配置问题
   （当前示例为 `["*"]`）。
4. **报 `证书` / TLS 错误** → 服务器时间、证书有效期（0.1.1 证书到 2026-12-05）或信任链。

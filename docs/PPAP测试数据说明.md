# PPAP 测试数据说明

日期：2026-10-14。

这组数据用于验证 PPAP 任务、结构化输入、编制检查、版本和下载功能，也可核对已有资料识别、检测数据表格、缺项定位和版本修改对照。全部为确定性的合成测试数据，以 `[合成测试]`、`TEST-PPAP-` 和 `synthetic_demo_only` 标识，不使用供应商样例中的历史业务值、检测值、签字或批准结论。

## 1. 当前测试任务

在项目页面登录后，进入「质量中心 → PPAP 编制」，将「任务范围」从默认的「正式任务」改为「测试任务」，刷新列表，按下列零件号选择任务。三份任务的模式均为 TEST，创建后不能改为 REAL。

| 零件号 | 内容 | 测试范围内的预期结果 |
|---|---|---|
| `TEST-PPAP-20261014-LH` | 左侧 A 柱饰板；13 类输入、1 个尺寸超差、1 个测量值缺失 | `BLOCKED` |
| `TEST-PPAP-20261014-RH` | 右侧 A 柱饰板；独立规格与测量、MSA、过程能力、输入变化后的新版本 | `COMPILED` |
| `TEST-PPAP-20261014-MISSING` | 未录入资料、未确认适用性 | `BLOCKED` |

实际状态和版本数量以页面为准。首次种子生成时，左侧/缺项各为 V1，右侧有 V1/V2；后续修复编制器、导出器或修改测试资料会产生新版本，历史文件继续保留。

左右任务各有 22 条输入，覆盖产品基础信息、工序、工序关系、特性、检验原始值、MSA、过程研究、材料记录、设备包装、客户要求、工程变更、实物记录和客户处理要求。左右使用相同特性编号、独立记录和规格：左侧长度名义值 100 mm，右侧 102 mm；左侧间隙名义值 5 mm，右侧 6 mm。

右侧 `COMPILED` 仅表示测试范围内的本地编制完成。其外部原件条目设为按需提供、MSA/过程研究设为留存，依据明确标注为合成测试范围；不能将这套测试适用性当作真实客户规则。测量系统和过程研究的客户判定规则仍待确认，25 个过程样本会保留小样本提示。PFMEA/控制计划的工程资料没有补造。

种子创建未进行内部批准、客户提交或客户接受。PSW 的供方签字和客户批准保持空值。

## 2. 建议检查顺序

1. 选择右侧任务，打开「编制与检查」，展开「尺寸结果」「测量系统分析」「初始过程研究」，查看原始输入、计算数值和待确认提示。
2. 打开「审核与版本」，查看历史版本和最新版本，下载对应 Excel。右侧首次生成的 V2 由一条合成客户处理说明变化产生；同一编制器下相同输入再次编制复用已有版本，升级后生成的新版本不覆盖旧文件。测试标识应出现在全部工作表及打印页脚。
3. 选择左侧任务，查看尺寸结果。6 条结果应包含 4 条 `OK`、1 条 `NG`、1 条 `MISSING`。这些是测试规格下的尺寸比对结果，不是正式客户批准。
4. 如需测试修正，在「工程与检验输入确认」选择检验原始值，保持原记录键和 `LEFT` 侧别，补录对应测试记录。原记录键分别为 `TEST-LEFT-DIM-TEST-CHAR-LENGTH-3` 和 `TEST-LEFT-DIM-TEST-CHAR-GAP-3`；测点分别为 `TEST-LEFT-TEST-CHAR-LENGTH-3` 和 `TEST-LEFT-TEST-CHAR-GAP-3`。可将测试长度改为 100.12 mm、缺失间隙补为 5.05 mm，保留来源中的合成测试说明，再编制查看新版本。其他工程资料缺项仍应显示。
5. 选择缺项任务，查看未确认适用性、基础资料、工序和特性等缺项原因与责任岗位。缺项时可以下载草稿，但不能批准。
6. 核对测试模式限制：真实关联字段、批量取证和客户状态操作应不可用。测试任务可以走本地内部审核/归档，但仍受零阻断、快照、文件校验和登录角色检查约束。
7. 核对特性防重复：尝试用新的记录键添加同一任务、特性编号、侧别的规格，应拒绝且不覆盖原记录。修正规格应载入原记录，用原记录键保存；左右独立任务中同名特性不应互相覆盖。

### 2.1 只读核对输入辅助与版本差异

本轮可以沿用这三份 TEST 任务，不需要创建真实订单、工单或检测记录。先只查看与载入，未点击确认保存时不会改变已登记资料：

1. 在右侧任务的「工程与检验输入确认」选择「产品基础信息」，查看客户、零件和版次建议及字段来源。建议只在空字段出现，仍需人工核对；任务元数据不是外部原件。
2. 选择检验原始值、MSA 或过程研究，核对侧别为 `RIGHT`，在「从已确认特性选择」选择一个明确特性。应显示同侧已确认的编号、单位或允许的规格建议，不应自动复制历史实测值、研究样本、方法或判定阈值。测量来源仍需填写，不能用规格来源冒充。
3. 在「已确认输入」中分别载入 MSA 和过程研究记录。MSA 应按现有评价人、零件和测次展示；样本和子组按原始数量、顺序及边界展示。空单元格表示缺测，不显示为 0；新建空表不出现固定采集方案。
4. 选择缺项任务，在「编制与检查」按阻断项/全部发现、条目和岗位筛选。已有明确位置的发现点击「去补充」应转到准备页对应位置；规则与无法唯一定位的发现应说明原因。实时发现数量和已登记未处理问题数量分别显示。
5. 对已有原记录的发现点击「去补充」，检查载入后的记录键、来源类别、来源引用、侧别和明确 `null` 是否保留。没有对应原记录时不得载入另一条测量记录。
6. 在右侧任务的「版本修改对照」指定已有历史版本，展开字段和数组原值。应看到所选版本与当前资料、来源引用及影响条目；旧版本未保存完整原值时明确显示无法还原，不据当前值猜测。

若要测试修改、缺测或非法输入，应明确在 TEST 任务中操作并确认来源。非法数值修正前不能保存；确认保存是独立的持久操作，之后重新编制才生成新版本。版本对照、筛选和载入修订不改变批准文件。

## 3. 重复创建与存储

后端已启动且本机项目登录配置可用时，在仓库根目录 PowerShell 执行：

```powershell
& '.\.conda-env\python.exe' '.\backend\seed_ppap.py' --label 20261014
```

同批任务已存在时只回读和下载已有文件，不覆盖人工修改、不重复建任务。如果需要一套独立数据，使用新的标签，例如 `--label 20261014B`。脚本使用已有后端依赖，本次无需新增依赖。

脚本只允许本机后端，通过正常项目登录接口取得 `quality_manager` 会话。密码不作为命令行参数，不写入测试记录，Cookie 只留在请求客户端内存中。脚本结束时退出它自己的会话，不清除浏览器会话。

任务及输入保存于本地 `ppap_*` 表。系统产物保存于配置的 PPAP 受控目录，下载副本和不含凭据的测试记录保存于 `backend/data/ppap_seed/20261014/`。这些数据目录已被 Git 忽略。

测试种子脚本不关联真实订单或工单，不调用 ERP/MES 取证或写入，不修改验收规则，不伪造客户原件，也不调用批准、豁免、归档和客户状态接口。模式隔离还由后端强制执行：正式任务拒绝合成测试来源、不支持的来源类别和测试包引用，嵌套资料包同样检查历史来源快照。

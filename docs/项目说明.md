# 项目说明：汽车零部件工厂四智能体协作平台

> 本文面向第一次了解项目的项目使用者和审阅者。它回答“项目解决什么问题、系统怎么组成、已经做到什么、哪些地方有边界”，不承担部署命令的职责。部署请看 [`部署指南.md`](部署指南.md)，页面功能请看 [`功能介绍.md`](功能介绍.md)。

## 一句话介绍

这是一个把报价、采购、生产跟单和质量管理串成一条业务链的智能体平台。系统从真实 ERPNext 和 OpenMES 读取业务数据，由四个专业智能体协同分析；涉及真实系统写入的动作必须经过人工审批、写回和回读验证。

项目面向汽车零部件生产协同场景，用于功能验证和业务验收。仓库不包含本机密码、Token、API Secret 或生产数据；文档里的 `TEST_`、`DEMO_` 编号是可复现的测试数据标记。

## 项目要解决的问题

汽车零部件工厂的一笔订单通常会跨过多个系统和岗位：销售先确认价格与交期，采购处理原材料缺口，生产跟踪工单和完工速度，质量人员处理 NCR 并判断能否发运。只看一个系统或只让一个问答机器人回答，容易出现数据口径不一致、审批缺失和无法追溯的问题。

本项目把这些环节放进同一个操作界面，同时保留外部系统作为业务事实来源：

- ERPNext 提供客户、物料、BOM、价格、库存以及销售/采购草稿；
- OpenMES 提供工单、批次报工、质量问题、检验和生产状态；
- 后端协调四个智能体，记录每次调用、数据来源和结果；
- 前端把分析、审批、跟单和质量待办放在同一条业务流程中。

## 四个智能体的分工

| 智能体 | 主要工作 | 典型结果 |
|---|---|---|
| 报价 Agent | 读取 BOM、价格和库存，分析成本、毛利和交期 | 报价分析、成本影响、交期依据 |
| 采购 Agent | 展开 BOM，计算缺料，比较供应商价格和交期 | 缺料清单、供应商方案、采购草稿建议 |
| 跟单 Agent | 关联销售订单和 MES 工单，读取生产进度和实测报工 | 完成率、速率型 ETA、延期/临期判断 |
| 质量 Agent | 汇总质量资料、NCR 和发运条件 | 质量待办、处置建议、发运门禁判定 |

## 一条完整业务链

```text
询价
  → 报价分析
  → 人工批准
  → ERPNext 销售订单草稿
  → 缺料分析与供应商方案
  → 人工批准
  → ERPNext 采购订单草稿
  → OpenMES 工单下达与生产跟单
  → 质量问题处置
  → 发运门禁判定
```

页面上的步骤状态以已加载的业务对象和真实接口回读为依据，不因为用户跳转过页面就把步骤标记为完成。

## 系统架构

```text
浏览器 5173（React + Vite）
        │
后端 API 9000（FastAPI，智能体协调、审批门禁、业务留痕）
        ├── ERPNext 8080（订单、物料、BOM、库存、草稿）
        ├── OpenMES 80（工单、报工、质量、检验）
        └── SQLite（默认业务留痕库，可选 PostgreSQL）
```

DeepSeek 只负责协同问答中的语言理解和组织回答；没有配置 DeepSeek 时，问答功能会明确报配置缺失，其余确定性业务能力仍按实际数据运行。

## 项目的三个设计原则

### 1. 数据真实

数字和状态优先来自 ERPNext/OpenMES 的真实接口，并带有来源或记录编号。接口连不上、主数据缺失或上游不支持时，页面显示数据缺失或不支持，不用固定值冒充结果。

### 2. 写入有门禁

读数据可以由智能体分析；写真实系统必须经过：

```text
建立审批 → 人工确认 → 写回上游系统 → 回读验证
```

重复操作要能识别已有记录，避免重复创建。AI 不以服务端集成账号代替用户完成审批。

### 3. 过程可追溯

每次智能体调用都会记录智能体、技能、参数摘要、耗时和结果摘要。审批、写入和回读也保留业务编号，方便验收后复查。

## 已实现的主要能力

- 报价分析、成本与毛利计算、交期依据展示；
- BOM 展开、缺料分析、供应商方案对比；
- 销售订单草稿和采购订单草稿的审批后写入；
- MES 工单关联、现场报工和按实际速率计算 ETA；
- 质量问题登记、NCR 处置、解决和关闭流程；
- 质量待办、生产延期/临期和缺料协同事件；
- 发运门禁判定和“去处理”导航；
- 真实模式与 Mock/fixture 测试数据隔离。

完整页面地图和使用方式见 [`功能介绍.md`](功能介绍.md)。

## 当前边界

以下内容必须按“当前系统不支持”或“数据缺失”理解：

- OpenMES 没有对应接口的订单级质量放行和实际发运执行；
- 没有 SN 级追溯接口时，不提供单件追溯结论；
- 没有 BOM、价格、库存、工艺模板或报工记录时，不套固定公式补结果；
- `TEST_`、`DEMO_` 数据只用于验收和验收，不能描述为真实生产记录；
- 当前真实环境复现流程已提供，但在另一台全新 Windows 电脑上的完整从零重放仍需单独记录验证结果。

## 给项目审阅者重点看什么

建议按下面顺序了解项目：

1. 看四个智能体如何分工，以及为什么要连接 ERPNext 和 OpenMES；
2. 看一笔订单如何从报价走到采购、生产和质量门禁；
3. 看真实数据缺失时系统是否如实阻断，而不是生成漂亮但没有依据的答案；
4. 看写入前的人工审批、回写和回读验证；
5. 看页面上的调用链和业务编号能否复查全过程。

现场操作顺序见 [`业务流程与验收.md`](业务流程与验收.md)。

# 项目文档索引

这里按读者和任务整理文档。第一次接触项目时，不需要按文件名逐个阅读；先选择下面的一条路线即可。

## 给老师、评委和第一次了解项目的人

1. [项目说明](项目说明.md)：项目解决什么问题、四个智能体怎么分工、业务链怎么走、当前能力和边界是什么。
2. [功能介绍](功能介绍.md)：逐页说明系统有什么功能、用户在哪里操作、审批门禁和真实/Mock 数据怎么区分。
3. [演示流程与验收](demo_runbook.md)：现场演示前检查、推荐演示顺序、每一步应该看到什么，以及已知限制。

## 给需要部署的同学

1. [真实环境复现部署](真实环境复现部署.md)：Windows 上重新部署 ERPNext、OpenMES、后端和前端，填写本机密码和 Token，并导入演示数据。
2. [同学电脑部署方案](同学电脑部署方案.md)：说明真实复现版、本地演示版、数据安全和验收边界。
3. 根目录 [README](../README.md)：提供最短路线、端口、启动入口和常见排障入口。

部署文档中的密码、Token、API Secret 只能填在自己的本机文件里，不能发到聊天或提交到 GitHub。`TEST_` / `DEMO_` 数据只用于演示，不代表真实工厂生产记录。

## 给项目维护者

1. [开发维护](开发维护.md)：测试命令、真实环境启动、提交前检查和文档分层规则。
2. [当前状态与整改计划](current_status_and_fix_plan.md)：真实代码、接口、测试、运行记录和遗留问题的证据账本。
3. [后续开发总计划与 AI 接手说明](AI_HANDOFF_PLAN.md)：当前路线、边界和验收标准。
4. `handoff_2026-*.md`：按日期保存的专项交接记录，只用于了解实现背景，不能代替当前状态文档。

## 文档维护规则

- 面向同学和老师的文档只写实际可操作的步骤，先说前置条件和预期结果。
- 面向维护者的文档记录实现依据、测试命令和验证边界，不放进新手推荐路线。
- 未经测试或真实接口验证的内容写成“计划”“待验证”或“当前限制”。
- 功能、启动流程或页面入口变化后，同步更新 README、功能介绍和演示流程。
- 不在文档、截图或示例命令中写入真实密码、Token、API Secret、Cookie 或数据库文件。

历史资料中包含早期 ACPs 依赖说明；它只用于追溯来源，不改变本项目的本地部署方式。

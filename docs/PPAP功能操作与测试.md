# PPAP 功能操作与测试

更新日期：2026-10-15。本文对应当前项目页面和新建的 `20261014STEP` 测试批次。

## 1. 先理解它在做什么

本项目的 PPAP 模块把一个零件的基础信息、工程资料、检验原始数据和来源整理成可检查、可审核、可追溯的文件包。

操作顺序是：任务信息 → 确认条目适用性 → 准备资料 → 编制及一致性检查 → 补充/修订 → 人工审核 → 版本冻结与归档。

PPAP 任务不是 MES 生产工单。正式任务可以关联 ERP 订单、MES 工单等资料来源，但 PPAP 的输入、运行、审核和文件索引保存于本项目的 `ppap_*` 表，文件保存于 PPAP 受控目录。编制 PPAP 不会向 ERP/MES 写入，也不代替原有 NCR 处置、质量放行或发运审批。

| 2 | `TEST-PPAP-20261014STEP-LH` | `PPAP-20261014125106-541a37` | 22 条输入，33 个实时阻断项，V1 草稿；练习尺寸异常和缺测修订 |
| 3 | `TEST-PPAP-20261014STEP-RH` | `PPAP-20261014125110-6e3870` | 22 条输入，0 个实时阻断项，V1/V2 草稿；查看研究表格、版本，亲自练习审核归档 |

页面使用「确认要求 → 准备资料 → 编制与检查 → 审核与归档」四阶段。顶部下一步是导航建议，不会自动保存、编制或批准。测试批次的初始表不是当前状态证明；已有人工修改、重新编制或审核时，以实际回读结果为准。

## 3. 建任务与确认适用性

先打开 MISSING 任务的「确认要求」。基本信息已由种子填好；查看当前适用性及其依据，已确认的要求不需要再次提交，变更应有明确依据。展开「任务信息与业务关联」，认识客户、零件、侧别、图纸版本、工程变更等级和提交原因。

若要亲自体验创建，可以点击「新建 PPAP 任务」，选择测试模式，填写另一套明确标记的测试信息，例如零件号 `TEST-PPAP-MANUAL-01`、名称 `[合成测试] 操作测试零件`、客户名称 `[合成测试] 非真实客户`、侧别左件。不知道的图纸版本、提交等级等不要用猜测值补齐。

「条目适用性确认」显示当前项目目录的 22 个条目。这是项目内部目录，不代表所有客户都固定要求提交这 22 项。

| 选择 | 含义 |
|---|---|
| 提交 | 本任务确认必须提供；相应必需资料缺失会阻断内部批准 |
| 保留 | 留存备查，仍显示资料是否就绪 |
| 按要求提供 | 按实际要求取得及提供，不等于已取得该资料 |
| 不适用 | 必须说明明确依据，不可用来消除缺项凑齐状态 |
| 待确认 | 尚未确认规则，不能当作已完成 |

页面建议值只是参考。确认自己的测试范围及依据后再点击「确认当前选择」。既有 LH/RH 已带明确测试适用性；学习时先查看，不需把它们改成全部不适用。

## 4. 自动识别与输入确认

进入 MISSING 的「准备资料 → 录入资料」，点击「基础与客户要求」，在「资料类型」选择「产品基础信息」。空字段应带入本任务已有的零件号、名称、客户及版本，并显示来源。它们此时只在表单里，点击「确认并保存输入」才会写入。

核对字段和来源后，按以下步骤确认保存结果：

1. 点击「确认并保存输入」。按钮应显示「正在保存…」并禁用，附近显示保存进度。
2. 等待「保存成功，已回读确认」。页面会自动展开「已确认输入」，突出显示刚保存的记录，并显示记录键、侧别、来源、确认人及时间。
3. 本批 MISSING 初始为 0 条输入；首次保存产品基础信息后应为 1 条。修订已有记录时，条数通常不增加，应核对该记录的最新内容。
4. 在表单中继续修改一个字段，观察「有修改尚未保存」提示。已确认列表仍显示上一次保存的值；不需要保留的修改可以重新载入原记录，载入本身不会保存。

如果显示「保存请求已成功，但记录回读未完成」或「保存结果未确认」，点击「重新读取已保存记录」。该按钮只查询，不再提交保存；核对完成前不要重复提交。明确的保存失败或必填校验会在输入区域说明原因，保留已填内容，按原因修正后再保存。输入保存反馈更新没有新增依赖或数据库迁移；本机前端开发服务运行时，刷新网页即可使用。

进入 RH 的「准备资料 → 录入资料」，点击「检验与研究」，在「资料类型」选择「检验原始值」并保持右件侧别，在「从已确认特性选择」选择 `TEST-CHAR-LENGTH`。应带入同侧特性编号、单位和允许的规格字段；实测值、测点及检测来源仍需实际资料。选择其他特性时，只更新尚未手工修改的预填值。

多个候选需要明确选择；重复或矛盾规格不预填。人工值、主动清空、明确 null 均优先于建议。规格来源显示在字段旁，不能冒充本次测量来源。

13 类输入可以分为以下内容：

| 输入 | 用途 |
|---|---|
| 产品基础信息 | 统一零件、客户和图纸版次等信息 |
| 工序、工序关系 | 整理工艺流程和前后关系 |
| 产品/过程特性 | 定义特性编号、侧别、单位和有来源的规格 |
| 检验原始值 | 保存测点、实测值、缺测及测量来源 |
| MSA 原始研究 | 保存评价人、零件和重复测量数据 |
| 过程研究原始样本 | 保存按原始顺序的样本及子组 |
| 材料/性能证据 | 登记实际材料、试验及报告引用，记录本身不等于已验证报告 |
| 设备与包装 | 整理设备、包装项目和数量等确认资料 |
| 客户特殊要求 | 记录要求原文、条款和来源 |
| 工程变更记录 | 记录已知变更内容和编号 |
| 实物记录 | 登记样品、检具等流转记录，不因生成表格而产生实物 |
| 客户处理要求 | 编制输入说明；与后面的客户提交/接受状态分开 |

## 5. 原始研究数据的表格

打开 RH「已确认输入」，找到 `TEST-RIGHT-MSA-01`，点击它的「载入修订」。应看到 3 位评价人、10 个零件标识、每件 3 次测量，共 90 个原始数值格。

再查看 `TEST-RIGHT-PROCESS-01`：有 25 个原始样本、5 个子组，每组 5 个数值。表格保留原有顺序及子组边界，不自行重排。

- 看看「新增评价人」「新增零件」「增加测次」「新增原始样本」「新增子组」分别调整什么。新格是缺测，不生成测量值。
- 空格保存为 null，表示缺测，不能当成 0。非法数字会标记并阻止保存。
- 修改测试单元格后，先检查来源、研究方法和规格，再确认保存。
- 「高级 JSON」用于核对原结构；未识别结构不会被强行转成表格或静默删字段。

MSA 根据多人、多个零件的重复测量计算差异；过程研究根据规格和原始样本计算 Cp/Cpk/Pp/Ppk 等指标。计算出数值不表示客户判定已通过，未确认规则仍显示待确认。当前种子的过程研究会保留 25 样本对应的小样本提示。

## 6. 编制、检查与下载

在 RH「编制与检查」点击「请求编制草稿」。系统整理条目内容、运行 12 类检查、记录缺项冲突并生成文件包。

相同输入再次点击应复用已有版本；输入、规则或编制器发生变化才需要新的版本。点击「运行一致性检查」会更新检查记录，但不要把它当作一次新的文件导出。

查看「条目内容预览」，重点展开提交清单、过程流程图、尺寸结果、MSA、初始过程研究、PSW 和附件目录。系统能整理有来源的内容；缺原件、工程基准或判定方法的地方仍保持待补。

到「审核与归档」点击「下载 V2」（版本变化时选当前最新草稿）。工作簿有 26 张表，包括概览、提交清单、22 个条目表、缺项与冲突、来源索引。各表带测试标识；签字和客户批准留空。修改下载副本不会更新系统原输入，也不会替换受控审核文件。

## 7. 缺项定位与尺寸修订

先在 MISSING「编制与检查」查看「缺项与补录位置」：

1. 「发现范围」在阻断项/全部发现之间切换。
2. 用条目和责任岗位筛选，查看缺什么、依据及谁需要确认。
3. 点击已提供明确位置的「去补充」，应进入对应表单或资料区域。
4. 需要业务规则或无法唯一定位的项目只说明原因，不提供猜测入口。

实时检查发现和已登记问题分别统计。定位不保存，也不会把发现改成已解决。

然后打开 LH「尺寸结果」，初始 6 条结果为 4 个 OK、1 个 NG、1 个 MISSING。这里只是合成测试规格下的尺寸比对。

| 修订记录键 | 初始值 | 本地功能测试可用的修订值 |
|---|---|---|
| `TEST-LEFT-DIM-TEST-CHAR-LENGTH-3` | 100.65 mm，超差 | 100.12 mm |
| `TEST-LEFT-DIM-TEST-CHAR-GAP-3` | null，缺测 | 5.05 mm |

找到原记录点击「载入修订」，保留 LEFT、原记录键和合成来源。缺测记录需要先取消「实测值确认无值」再输入 5.05，并核对原缺失说明。上述数字仅用于测试修改功能，不是对真实测量数据的处理建议。

确认保存后重新编制，对比 V1 与新版本。尺寸异常/缺值应随输入修正而变化；LH 还有其他原件、工程和规则缺项，修好两个尺寸并不意味着任务可批准。

「处理此项」用于记录修正或人工接受依据。仍然检出的发现不能标成数据已修正；「人工接受并留痕」也不能绕过仍存在的阻断项。重新检查/编制后按实际问题状态处理，已解决的问题不要重复处理。

同侧同编号规格只能用原记录键修订。换一个键重复录入不会形成第二条可用规格。

## 8. 版本修改对照

入口在「编制与检查」的「版本修改对照」，不是下载按钮。选择「对照版本」，比较当前已登记资料与指定历史版本。

能查看数据集、记录键、侧别、字段旧/新值、来源和受影响条目。数组可以展开；未提供、明确 null 和历史未保存原值分别显示。无法核对的历史原值不会从当前数据猜测。

对照操作只读，不刷新 ERP/MES、不保存，也不产生新版本。旧草稿及已批准文件继续保留。

## 9. 内部审核、退回、批准与归档

使用 RH。先核对最新草稿、实时零阻断、资料快照和文件完整性，再到「审核与归档」。审核按钮可用还取决于当前项目登录及质量角色。

### 9.1 体验退回

1. 在「审核 / 归档意见」填写测试意见，例如「功能测试：请补充本次测试资料修订说明」。
2. 点击最新版本的「提交 Vn 审核」。
3. 填写退回意见，点击「退回修改」。查看审核记录中的版本、账号和意见。
4. 到「准备资料」，载入 `TEST-RIGHT-HANDLING-01`，保留原内容和合成来源，只将备注改为「TEST：根据退回意见补充本地测试资料修订说明」。
5. 确认保存，再编制新版本。不能对已退回的同版本直接改作批准决定。

### 9.2 体验批准和归档

1. 查看新草稿及差异，核对仍无阻断。
2. 提交新版本审核，填写「功能测试：已核对当前测试输入、来源和版本；仅用于本地测试」等明确意见。
3. 点击「批准此版本」。该版本冻结，后续输入变化只能产生新草稿。
4. 点击该版本的「归档 Vn」，再下载并查看审核记录。

这些操作由你亲自确认执行，种子脚本没有代你批准或归档。同账号编制与审核会显示岗位分离提示；测试内部批准不代表正式客户批准。

## 10. 来源、问答与其他能力

### 10.1 原件登记及批准包引用

「登记原件或引用已批准包」登记的是维护人员已放入受控目录的文件或明确引用，不是文件上传。填写来源编号、说明、实际版次和用途；设计原件需版次，已批准包需产物 ID。

一份功能测试说明不能当作设计图纸、检测报告或客户批准来填齐条目。没有实际原件时保留缺项；已有文件还需校验实际内容及绑定条目。测试包和正式包不能互相引用，嵌套引用也会核对来源。

### 10.2 正式取证与客户记录

TEST 禁止真实 ERP/MES 关联和取证；这些按钮不可用是模式限制。正式任务按明确关联读取资料，成功有记录（OK）、成功无记录（EMPTY）、读取失败（ERROR）分别展示，空数据与失败不能解释为资料齐全。

「客户处理记录」仅供正式任务在内部批准后依据实际提交、接受或退回记录登记。TEST 不能写这些状态，因此本批只能认识其含义，不能模拟客户接受。内部批准、客户接受、NCR 关闭、发运允许分别成立，不相互替代。

### 10.3 运行与追溯

从任意阶段点击「来源与操作记录」，查看取证覆盖、任务留痕、每次编制的有序步骤、实际调用链和运行摘要。查看失败与缺项原因，不把运行完成当成内部批准，也不把本地测试调用当成真实上游取证。

### 10.4 协同问答

PPAP 已提供只读任务检索、适用性、状态、缺项解释、取证计划和版本查询能力。可以在「AI 协同问答」明确提供任务 ID，询问「这个 PPAP 任务还缺哪些资料」「各条目适用性是什么」「有哪些文件版本」。是否调用这些技能，以页面实际调用链为准。

问答不负责新建任务、保存输入、编制、审核决定或归档；这些操作仍回到任务页面由已登录用户确认。

## 11. 操作完成核对

- [ ] 能解释任务信息与 MES 工单的区别。
- [ ] 能说明四种条目适用性，并知道建议不是已确认规则。
- [ ] 能识别哪些字段可以复用，哪些测量/工程数据必须有来源。
- [ ] 能通过就近保存反馈和回读记录确认提交结果；回读未完成时只重新查询，不重复提交。
- [ ] 能操作 MSA、样本及子组表格，并区分缺测与 0。
- [ ] 能查看缺项、定位补录并保留原记录键和侧别。
- [ ] 能编制草稿、下载 Excel、修订并查看版本差异。
- [ ] 能亲自完成一次退回→修订→新版本→批准→归档。
- [ ] 能查询留痕，并区分内部批准、客户接受及原质量/发运流程。

本批只能验证项目内部模板的功能，不替代正式客户 PPAP 验收。正式模板、真实检测资料和业务规则仍按[PPAP 操作指南](PPAP操作指南.md)处理。

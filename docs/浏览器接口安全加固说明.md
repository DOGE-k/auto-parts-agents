# 浏览器登录与聊天历史隔离

本轮按用户明确选择，只保留网页强制登录和聊天历史隔离。此前额外添加的登录/IP节流、问答分钟/日额度、并发上限、64KiB请求体和8000字符限制、强制Origin检查已撤回。原来的CORS配置和业务审批/写入角色门禁保持。

## 配置与启动

1. 已有数据库继续保留。迁移`f31d9a2c6b10`增加可空的`assistant_sessions.owner_subject`；新环境先执行`python -m alembic upgrade head`。不回滚业务库，也不删除已有聊天。
2. `PROJECT_AUTH_REQUIRE_LOGIN=true`默认开启；所有浏览器业务API、浏览器主应用的旧`/aip/`和接口文档需要项目登录。健康、表面说明及必要登录端点可公开，`/auth/me`仍自行检查会话。
3. `PROJECT_AUTH_COOKIE_SECURE`必须与当前访问协议一致：HTTP演示入口设`false`，HTTPS入口设`true`。`HttpOnly`和`SameSite=Lax`保留。项目密码通过已有部署配置提供，不在文档或代码里填写。
4. 前端API默认同源`/api`，HTTP演示通过Vite代理访问后端。不要把`127.0.0.1:9000`固化为访问者浏览器的API地址。
5. 旧的`PROJECT_AUTH_ALLOWED_ORIGINS`、`PROJECT_LOGIN_ATTEMPTS_PER_MINUTE`、`PROJECT_ASSISTANT_REQUESTS_PER_MINUTE`、`PROJECT_ASSISTANT_REQUESTS_PER_DAY`、`PROJECT_ASSISTANT_MAX_CONCURRENT`、`PROJECT_ASSISTANT_GLOBAL_CONCURRENT`已不再由本中间件使用，应清理本轮部署额外加入的这些覆盖项，避免误认为它们还会生效。

本次不强制新增HTTPS、私有Unix socket或单worker部署。原有模型、ERP/MES连接限制与服务自身的执行超时保持；撤回的是本轮添加的浏览器访问限制，不是承诺所有上游服务都没有限制。

## 会话与审计边界

新浏览器聊天记录登录账号的`owner_subject`。会话列表、消息、继续问答和对应协调运行记录只对该账号可见；同步与SSE入口均在使用已有会话前检查归属。不同账号或不存在的会话返回404，不能通过提供他人的ID读取内容。

旧历史和平台进程产生的无归属会话继续保留NULL，不自动分配给第一个登录用户，不删除，在个人历史中隐藏。若以后确需迁移归属，应依据可信记录另行处理。

无聊天`session_id`的团队业务运行审计仍供已登录项目用户共享。审批、报工、ERP/MES写入仍走原有人工身份和角色检查，未登录不回落到上游集成账号替人操作。

前端在服务端确认项目会话前不挂载业务组件；退出或收到会话401时卸载业务界面并清理选中的聊天ID。项目Bearer会话在本地解析，不转发给ERP/MES。

## 与梧桐平台的区别

正式9443–9447的mTLS应用由独立`create_app`创建，没有安装浏览器Cookie门禁。本次不改AIC、证书、技能或平台接入认证，网页账号不作为梧桐调用方身份。

## 验证要点

- 匿名业务查询/问答被拒绝，合法项目用户可以登录并访问。
- 跨账号、旧无归属及不存在的会话不能读取或继续，自己的新会话正常。
- 登录请求和重复提问不再被本轮新增次数额度拒绝；多个流式问答不再被本轮新增并发上限拒绝。
- 超过旧浏览器附加字数/大小阈值的请求交回正常接口校验，不再由中间件额外返回413或字数错误。
- HTTP/HTTPS配置分别能够签发可用Cookie，退出后项目权限失效。

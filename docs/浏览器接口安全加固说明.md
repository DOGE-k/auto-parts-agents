# 浏览器接口安全加固说明

## 部署顺序

1. 备份实际数据库与配置。
2. 更新代码后，在 backend 目录运行项目环境的 `python -m alembic upgrade head`，新增迁移 `f31d9a2c6b10`（assistant_sessions.owner_subject，可空）。
3. 保持后端单个 worker，仅监听回环/私网。应用启动前准备项目用户；密码通过受保护的部署环境提供，禁止放进仓库或日志。
4. 前端构建部署到正式 HTTPS 入口；API 默认同源 `/api`。设置 `PROJECT_AUTH_COOKIE_SECURE=true`。
5. 配置明确的同源地址，并确认反向代理保留 Host；仅信任实际反向代理的转发地址，不能无条件相信客户端 X-Forwarded-*。本中间件不会自行信任这些头。
6. 外部匿名请求应收到401；合法项目登录后验证业务与SSE；另测正式mTLS AIP进程不受浏览器Cookie门禁影响。

## 默认策略与环境变量

- `PROJECT_AUTH_REQUIRE_LOGIN=true`：生产默认；全部 `/api/`、浏览器主应用的旧 `/aip/`、API文档都要求项目登录。仅健康、表面说明、登录与退出等必要端点公开，`/auth/me`另有自身登录检查。`false`仅用于明确隔离的离线接口合约测试，生产禁止关闭。
- `PROJECT_AUTH_ALLOWED_ORIGINS`：逗号分隔的完整 `https://域名[:端口]`。同时接受ASGI服务端确认的同源Host。默认开发源仅 localhost/127.0.0.1 的5173/5174。Cookie认证的非安全方法需要允许的Origin；无Origin的Bearer维护客户端可用。
- `PROJECT_AUTH_COOKIE_SECURE=true`：HTTPS部署必设，保留HttpOnly和SameSite=Lax。
- `PROJECT_LOGIN_ATTEMPTS_PER_MINUTE=5`：每客户端IP每分钟登录尝试总数。
- `PROJECT_ASSISTANT_REQUESTS_PER_MINUTE=10`：每项目账号每分钟问答尝试数。
- `PROJECT_ASSISTANT_REQUESTS_PER_DAY=100`：每账号滚动24小时问答尝试数。
- `PROJECT_ASSISTANT_MAX_CONCURRENT=1`：每账号同时执行问答数。
- `PROJECT_ASSISTANT_GLOBAL_CONCURRENT=4`：整个浏览器服务同时执行问答数。

限流和次数额度是有界进程内计数，服务重启会重置，不能当作长期硬性账单上限。当前要求单worker；若增加worker或实例，应先接共享限流存储，并在模型供应方设置账户费用上限。并发名额覆盖SSE响应体完整生命周期，断开或完成后释放。问答请求体限制64KiB，问题限制8000字符。正式mTLS接入有独立调用方信任边界，未在本次修改其认证方式或注册信息。

## 会话与审计边界

新浏览器会话保存登录账号的owner_subject；列表、消息、继续问答和关联协调运行记录仅该账号可访问。普通业务运行审计（无聊天session_id）仍供已登录团队用户共享，原有写入角色权限保持。

历史会话与平台进程创建的无owner_subject会话保持NULL，不自动认领、不删除，在浏览器个人历史中隐藏。若需要迁移归属，必须另行根据可信记录确认；禁止把全部旧历史批量指给第一个登录用户。原件与数据库仍保留，可受控审计。

前端顶层登录门在服务端确认登录前不挂载业务组件；退出或项目会话401会卸载业务并清除浏览器中选中的聊天ID。失败请求不回落到上游集成账号，不使用匿名服务账号替代项目登录。

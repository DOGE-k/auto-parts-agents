# 部署指南：Windows 本地 ERPNext + OpenMES

> 读者：第一次在自己电脑部署本项目的使用者。本文按实际操作顺序编写，命令默认在 **PowerShell 的仓库根目录**执行；只有特别说明时才切换目录。文档整理日期：2026-10-04。本文根据当前脚本和已反馈的问题整理，尚未完成一台全新 Windows 环境的完整重放。

完成后，你会有本机的 ERPNext、OpenMES、业务后端和操作界面。每台电脑使用自己的账号、密钥和数据库；“相同的验收步骤”不表示共享同一份数据。

## 首次部署总览

| 步骤 | 你需要做什么 | 完成标志 |
|---|---|---|
| 1 | 安装工具、获取代码 | Docker 引擎和工具版本可读 |
| 2 | 运行准备脚本、填写服务密码 | 两个外部服务启动，配置文件已生成 |
| 3 | 创建 ERPNext 站点和 API 凭据 | ERPNext 可登录、根目录配置已填 |
| 4 | 配置 OpenMES 的两类凭据 | 集成 Key 已写入根目录配置 |
| 5 | 创建测试产线、导入基础和工单数据 | 物料、工单、质量问题可在本机查询 |
| 6 | 安装前端依赖 | Vite 依赖存在 |
| 7 | 启动并做业务验收 | 页面打开，查询有依据，写入有审批 |

首次安装要做完这七步。以后启动只需第 7 步，不必反复导入种子数据。

## 账号、密码和密钥总表

先知道每个值属于哪个系统，填写时再回来查：

| 项目 | 从哪里获得 | 填到哪里 | 用途 |
|---|---|---|---|
| 项目账号用户名与密码 | 首次部署时在根目录配置 | `.env` 的 `PROJECT_AUTH_USERNAME`、`PROJECT_AUTH_PASSWORD` | 登录本项目；审批身份和操作审计 |
| OpenMES 管理员账号与密码 | 首次部署时自己设置 | `services/OpenMes/.env` 的 `ADMIN_USERNAME`、`ADMIN_PASSWORD` | 后端连接 OpenMES、获取服务会话和集成 Key；不是页面项目账号 |
| ERPNext 数据库 root 密码 | 首次部署时自己设置 | `services/frappe_docker/.env` 的 `DB_PASSWORD` | ERPNext 建站时连接数据库 |
| ERPNext Administrator 密码 | 第 3 步建站时设置 | 在 ERPNext 登录页使用 | 管理 ERPNext，与数据库密码用途不同 |
| ERPNext API Key 和 Secret | ERPNext 用户的 API 访问设置 | 根目录 `.env` 的 `ERPNEXT_API_KEY`、`ERPNEXT_API_SECRET` | 本项目读 ERP 数据和审批后起草 |
| OpenMES 个人 Bearer 令牌 | 登录脚本获取，或 OpenMES 的 Settings → API Tokens 创建 | 根目录 `.env` 的 `OPENMES_TOKEN` | 后端访问 OpenMES 用户 API；不是页面项目账号，也不是集成 Key |
| OpenMES 集成 Key | 第 4 步脚本或管理员 POST 接口创建 | 根目录 `.env` 的 `OPENMES_ERP_API_KEY` | `/api/v1/erp/*` 接口，当前格式为 `omk_...` |
| 本地写入令牌（可选） | 需要高级联调校验时由维护人员生成随机字符串 | 根目录 `.env` 的 `REAL_WRITE_API_TOKEN` | 错误的调试令牌会被拒绝；普通项目登录写入不依赖它 |
| DeepSeek API Key | 自己在模型平台申请 | 根目录 `.env` 的 `DEEPSEEK_API_KEY` | AI 协同问答；未配置时该功能返回配置缺失 |
| 前端后端地址 | 准备脚本生成 | `frontend/.env.local` | 默认 `VITE_API_BASE_URL=http://127.0.0.1:9000/api` |

真实值只保存在本机。不要把 `.env`、完整 Token、密钥截图或数据库交给使用者；给他们仓库和本文即可。

## 第 1 步：准备工具和代码

安装并启动 Docker Desktop，使用 Linux 容器模式，确认 Compose v2 可用。还需要 Git for Windows、Python **3.12 或 3.13**、Node.js **20+** 和 npm。当前后端包不支持 Python 3.14。

在新 PowerShell 窗口执行：

```powershell
docker version
docker compose version
git --version
python --version
node --version
npm.cmd --version
```

**预期结果**：Docker 同时显示 Client 和 Server，其他工具输出版本。只有 Docker Client 时，先解决引擎未运行的问题。

获取代码，以下目录名只是示例，可选择自己的目录：

```powershell
git clone https://github.com/DOGE-k/auto-parts-agents.git
cd auto-parts-agents
```

本文主要使用端口 80/443（OpenMES）、8080（ERPNext）、9000（后端）、5173（前端）。默认使用 SQLite，不需要另装业务 PostgreSQL。镜像和数据会持续占用磁盘，先确认安装盘有可用空间；目前没有经过实测的最低内存、磁盘和首次安装耗时指标。

## 第 2 步：生成配置并启动外部服务

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1
```

该脚本会获取 OpenMES 与 frappe_docker 上游仓库、生成缺失的配置、启动两个独立容器项目、安装后端依赖并执行业务库迁移。它不覆盖已有配置，**也不会安装前端 npm 依赖、自动完成所有账号设置或自动导入全部业务数据**。

首次生成的文件：

- 根目录 `.env`：本项目连接配置；
- `services/OpenMes/.env`：OpenMES 配置；
- `services/frappe_docker/.env`：ERPNext 服务配置；
- `frontend/.env.local`：前端连接地址。

缺密码时脚本会等待。另开一个 PowerShell 窗口进入同一仓库目录，打开对应文件：

```powershell
notepad .\services\OpenMes\.env
notepad .\services\frappe_docker\.env
```

填写总表中的管理员账号/密码和 `DB_PASSWORD`，保存后回原窗口按 Enter。如果原窗口已经回到 `PS ...>`，表示本轮结束，要重新运行准备脚本。

**预期结果**：OpenMES 能在 [http://127.0.0.1/](http://127.0.0.1/)打开。首次 ERPNext 可能因尚未建站而不能通过 ping 检查；此时按第 3 步先建站，再重跑准备脚本，不必反复等待同一个检查。

## 第 3 步：创建 ERPNext 站点和凭据

### 3.1 一次性创建 localhost 站点

ERPNext 容器已启动、但尚未创建站点时，在仓库根目录完整执行下面两段。数组集中列出了实际使用的 Compose 文件，不能只复制后面的 `exec`：

```powershell
$erpCompose = @(
    "compose", "--project-name", "erpnext",
    "-f", ".\services\frappe_docker\compose.yaml",
    "-f", ".\services\frappe_docker\overrides\compose.mariadb.yaml",
    "-f", ".\services\frappe_docker\overrides\compose.redis.yaml",
    "-f", ".\services\frappe_docker\overrides\compose.noproxy.yaml",
    "--env-file", ".\services\frappe_docker\.env"
)
```

```powershell
docker @erpCompose exec backend bench new-site localhost --mariadb-user-host-login-scope=% --install-app erpnext
```

逐项填写：

| 提示 | 填什么 |
|---|---|
| `Enter mysql super user [root]:` | 用户名，直接 Enter 使用 `root`，这里不是密码 |
| `MySQL root password:` | `services/frappe_docker/.env` 的 `DB_PASSWORD` |
| `Set Administrator password:` | 为 ERPNext 管理员设置的登录密码 |

密码输入时可能不显示字符。站点名保持 `localhost`，参数为 `--mariadb-user-host-login-scope`。已有站点不要再次新建。

**预期结果**：安装 frappe 和 erpnext 完成，返回命令提示符；[http://127.0.0.1:8080/](http://127.0.0.1:8080/)可用 Administrator 和刚设置的密码登录。

### 3.2 生成 ERPNext API Key/Secret

在 ERPNext 搜索框搜索 **User**，打开用户列表，再打开本机用于连接的用户，进入设置中的 **API Access / API 访问 → Generate Keys / 生成密钥**。创建的 Key 和 Secret 填进根目录 `.env`。两者都需要，不能只填 Key。

维护时建议使用专用用户；如果本地初始化使用 Administrator，后续切换到专用用户前要确认其具备读取主数据及创建订单草稿的实际权限。本项目没有自动给专用用户分配全部角色。

打开配置：

```powershell
notepad .\.env
```

配置真实模式、项目账号和默认地址：

```dotenv
APP_ADAPTER_MODE=real
PROJECT_AUTH_USERNAME=admin
PROJECT_AUTH_PASSWORD=<本机项目账号密码>
ERPNEXT_BASE_URL=http://127.0.0.1:8080
ERPNEXT_API_KEY=<本机的 API Key>
ERPNEXT_API_SECRET=<本机的 API Secret>
REAL_WRITE_API_TOKEN=<可选：本机生成的随机字符串>
```

尖括号内容是说明，要替换成实际值。`PROJECT_AUTH_PASSWORD` 是项目登录所需的唯一人工账号密码；`REAL_WRITE_API_TOKEN` 只用于高级联调兼容校验，普通项目登录写入不要求填写。需要启用高级联调校验时，可在本机生成令牌：

```powershell
python -c "import secrets; print(secrets.token_hex(24))"
```

有些首次初始化还要求 ERPNext 完成系统自己的基础设置。页面要求设置时先完成它，再检查本项目的业务数据。配置完成后重跑准备脚本，使依赖安装、迁移和站点检查能继续。

## 第 4 步：配置 OpenMES 凭据

在仓库根目录运行：

```powershell
python backend\get_openmes_token.py
```

脚本从本机 OpenMES 配置读取管理员账号登录，获取个人会话，检查已有集成 Key；没有有效 Key 时通过管理员接口创建，再写回根目录 `.env`。**这是 OpenMES 的集成 Key，名称中的 ERP 不表示在 ERPNext 页面创建。**

确认终端没有 `FAILED` 或 HTTP 错误，并在本机配置中确认 `OPENMES_TOKEN` 和 `OPENMES_ERP_API_KEY` 已填写。不能只看命令退出就认为凭据正确。

两类凭据不可互换：

- **Settings → API Tokens** 生成的是个人令牌，用 `Authorization: Bearer ...`。完整前缀由当前实例生成，可能是 `8|` 或其他值，不能写死；
- **`omk_...`** 是机器集成 Key，用 `X-Api-Key`。项目需要 `erp:masterdata:write`、`erp:orders:import`、`erp:production:read`、`erp:quality:read` 四个范围。

`http://127.0.0.1/api/v1/api-keys` 是管理员 **POST API**，不是浏览器页面。直接在地址栏打开可能跳回 dashboard。OpenMES 默认是 80 端口；8080 属于 ERPNext。

如果脚本没有成功，按下面“手动创建集成 Key”处理，不要把个人令牌直接填进 `OPENMES_ERP_API_KEY`。

<details>
<summary>手动创建集成 Key（脚本失败时使用）</summary>

登录 OpenMES，进入 **Settings → API Tokens**，新建个人令牌并复制完整值。令牌有时效，过期需要重新生成。

在同一个 PowerShell 窗口、仓库根目录完整执行以下代码。它包含全部变量定义，不需要沿用另一个窗口的 `$baseUrl`：

```powershell
$baseUrl = "http://127.0.0.1"
$secureToken = Read-Host "输入刚创建的完整个人令牌" -AsSecureString
$adminToken = [System.Net.NetworkCredential]::new("", $secureToken).Password
$keyBody = @{
    name = "auto-parts-agents"
    scopes = @(
        "erp:masterdata:write",
        "erp:orders:import",
        "erp:production:read",
        "erp:quality:read"
    )
    is_active = $true
} | ConvertTo-Json -Depth 3
$createdKey = Invoke-RestMethod -Method Post -Uri "$baseUrl/api/v1/api-keys" -Headers @{
    Authorization = "Bearer $adminToken"
    Accept = "application/json"
} -ContentType "application/json" -Body $keyBody
$createdKey.plaintext_key
```

当前接口在响应顶层的 `plaintext_key` 返回一次性明文。复制该 `omk_...` 到根目录 `.env` 的 `OPENMES_ERP_API_KEY`，个人令牌则填到 `OPENMES_TOKEN`。不要分享这段输出的截图。出现 401 时更新个人令牌；403 时检查管理员权限。接口返回结构变化时停止并核对当前版本，不凭猜测取字段。

</details>

需要 AI 协同问答时，另在根目录 `.env` 填自己的 `DEEPSEEK_API_KEY`。未配置时仍可使用确定性业务页面，但问答会报配置缺失。

## 第 5 步：准备产线并导入测试数据

### 5.1 创建测试产线

登录 OpenMES（80 端口），进入 **Admin → Production → Lines → New Line**，也可尝试本机的 [http://localhost/admin/lines](http://localhost/admin/lines)：

| 字段 | 填写内容 |
|---|---|
| Name | `Demo Line 01`，名称可调整 |
| Code | `DEMO_LINE_01`，必须一致 |
| Active | 勾选 |

产线用于关联测试工单，不是密钥。种子脚本按 Code 查询它，不使用固定数字 ID。

### 5.2 首次导入

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1 -RunSeeds -RunRealDemoSeed
```

确认提示后会依次执行：

| 脚本 | 准备的数据 | 重跑边界 |
|---|---|---|
| `seed_erpnext.py` | ERPNext 公司、客户、供应商、物料、BOM、价格 | 要查看成功/跳过信息；跳过不等于数据全部正确 |
| `seed_openmes.py` | OpenMES 产品、工单和质量相关基础记录 | 质量问题可能重复新增，不能无限重跑整组 |
| `seed_supplier_data.py` | 供应商关系、交期、最小采购量和供应商价格 | 有查重，仍需检查回读 |
| `seed_real_demo.py` | 动态查重的 3 条 `TEST_` 工单与 1 条质量问题 | 使用本机主数据，复用已存在的匹配记录 |

**预期结果**：能在本机查到 `TEST_WO_PAGE_00023`、`TEST_WO_PAGE_00024`、`TEST_WO_PAGE_00025` 和 `TEST_SEED_QUALITY_00023` 标记的质量问题。实际数据库 ID 可以与作者电脑不同。

如果基础导入已成功，只需补齐产线后重试测试工单，不再运行整组：

```powershell
python backend\seed_real_demo.py
```

这组种子没有自动准备工艺快照、历史报工和所有检验记录。工单存在不表示一定能报工或计算 ETA；前置数据不足时按页面提示处理。

旧的 `seed_openmes_v2.py`、`seed_openmes_v3.py` 和 `seed_inspection_eta.py` 不属于新手流程，它们依赖固定 ID 或数据库结构。维护者查阅[开发维护说明](开发维护.md)，不要为消除“数据缺失”直接执行它们。

## 第 6 步：安装前端依赖

准备脚本只安装后端依赖。第一次启动前单独执行：

```powershell
Push-Location .\frontend
try { npm.cmd ci } finally { Pop-Location }
```

`npm ci` 按仓库的锁文件安装，适合首次复现；启动脚本提示的 `npm install` 也能用于安装依赖。完成后应存在 `frontend/node_modules/.bin/vite.cmd`。如果 npm 明确报某个安装脚本被阻止，要根据该包的实际错误处理，不能仅凭“没有漏洞”判断安装可用。

## 第 7 步：启动应用并验收

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_app.ps1
```

或双击 `启动应用.bat`。成功后打开 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。

进入 **系统连接**：

1. 检查 ERPNext 和 OpenMES 的实际连接状态；
2. 在 **项目账号**登录根目录 `.env` 中配置的项目账号；
3. 按[业务流程与验收](业务流程与验收.md)检查一条只读查询和一次受控写入；普通写入不需要填写高级联调令牌。

ERPNext/OpenMES 的账号、API Key、Secret 和 Bearer 令牌由后端服务读取配置文件，用于连接外部系统。高级联调设置只在需要手工排查认证时使用。

启动检查只能提供初步结果；模型 Key 是否有效、账号权限是否足够、数据是否完整，需要通过实际业务请求验证。

- [ ] 后端健康接口响应，前端可打开；
- [ ] 页面真实连接状态正常，`APP_ADAPTER_MODE=real`；
- [ ] 本机 ERP 数据、MES 工单和质量问题能查到；
- [ ] 若需要问答，模型配置有效，回答有数据依据；
- [ ] 项目账号可识别，写入后能回读，重复操作不重复创建；
- [ ] 停止再启动后数据仍在；
- [ ] 在团队交付记录中填写本机系统/镜像版本、完成日期、失败点与修复方式。

## 常见问题

| 现象 | 怎么处理 |
|---|---|
| ERPNext 首次拉取很久 | 下载与解压大镜像需要时间；进度或日志变化时等待，不反复中断 |
| `unexpected EOF` | 当前模板用 `frappe/erpnext:v16.36.0`；运行 `docker pull frappe/erpnext:v16.36.0`重试，再运行准备脚本；若自己改过版本，以本机配置为准 |
| Docker 的 `containerd`、`SIGBUS` 或 `bus error` | 退出并重开 Docker Desktop，确认 Client/Server 都正常后重试；恢复出厂设置会删除数据，不作为普通重试方式 |
| 缺少 `ADMIN_PASSWORD` 或 `DB_PASSWORD` | 按总表编辑对应服务的配置文件；等待中的脚本按 Enter，已退出的脚本重新运行 |
| OpenMES 集成接口 401 | 检查 `OPENMES_ERP_API_KEY` 是本机有效的 `omk_...`，不是个人令牌；运行第 4 步重新获取或创建 |
| OpenMES 接口 403 | 可能是 Key 范围不足或登录账号无权操作；按使用的接口检查权限 |
| 项目登录会话过期 | 页面到“系统连接”重新登录项目账号；OpenMES Bearer 令牌由后端服务维护，不作为页面审批身份 |
| `/api/v1/api-keys` 跳到 dashboard | 它是 POST API，按第 4 步调用，不在浏览器地址栏打开 |
| PowerShell 报“无效的 URI” | 新窗口没有旧窗口变量；完整复制第 4 步的定义和请求代码 |
| 找不到 `DEMO_LINE_01` | 创建产线，检查 Code 精确一致和 Active 开启，再仅重跑 `seed_real_demo.py` |
| `planned_qty` 或 `Issue title is required` | 当前脚本已使用 `planned_qty` 和 `title`；先确认拿到团队当前修复版本，不要靠改密码解决 |
| 前端依赖未安装 | 完成第 6 步；`node_modules` 不随 Git 分发 |
| 前端 5173 未响应 | 查看 `frontend/vite-5173.log` 和 `frontend/vite-5173.err.log`；确认端口没有被其他程序占用 |
| 后端 9000 未响应 | 查看 `backend/uvicorn-9000.log` 和 `backend/uvicorn-9000.err.log`；确认启动脚本所用 Python 已安装依赖 |
| 高级联调令牌错误 | 只有填写了 `REAL_WRITE_API_TOKEN` 才会校验该请求头；普通项目登录不依赖它。修改后端配置后重启 |
| 工单有数据，但 ETA 或报工不可用 | 工单不等于工艺模板、检验和报工齐全；按实际缺口准备数据，不能用固定数值代替 |

## 交给使用者时包含什么

提供仓库访问方式、本文、项目说明和业务流程与验收文档。不要分享本机 `.env`、数据库卷、完整密钥截图或日志。

本地复现和平台接入分别验收。若还要从梧桐平台发现或调用智能体，另看[平台接入与提交待办](比赛接入与提交待办.md)；本机 `localhost` 地址不会自动变成平台可访问的服务。

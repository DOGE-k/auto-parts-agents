### 已知坑

- **Git Bash 下 curl 传中文 JSON 会编码失败**：用 python 脚本或 `--data-binary @文件` + `Content-Type: application/json; charset=utf-8`
- **9001 端口曾出现旧代码后端进程**（显示过期数据）：接手后先 `netstat -ano | grep 9000` 确认只有 9000 在跑；发现 9001 监听要杀掉
- **浏览器测试**（in-app browser / node REPL）：标签页快照可能返回空（页面 stale），reload 或新开标签即可，不是代码问题
- 前端 dev server 检测到文件变更会自动重启，偶发 `Port 5173 already in use` 是旧进程未退，杀掉旧 PID 再启

## 3. 硬性规则（违反即返工）

1. 真实模式下不得静默回退 Mock；连接失败必须明确报错
2. 不得猜 ERP/MES 字段；新字段先读真实记录确认
3. **写入真实 ERP/MES 需要用户明确批准**（本会话用户已批准的写入范围见 §4.3）；草稿写入走审批门禁（approval_id + approved_by 校验，已持久化到数据库）
4. 写入后必须**回读确认**（read_back_verified）；草稿 docstatus=0 不得说成正式执行
5. 不得输出 Token/密码/API Secret/Cookie
6. 不得删除数据库或代码掩盖问题
7. 每完成一个阶段更新 `docs/current_status_and_fix_plan.md`（修改文件、真实记录编号、接口、状态码、authority、是否写入、回读结果、测试结果、遗留问题、下一步）

### 6.1 前端：采购 NO_SHORTAGE 时流程卡死（✅ 已修复，待浏览器复验）

**原现象**：报价数量 ≤ 库存（如默认 100 件）时，采购分析返回 `NO_SHORTAGE`（库存充足，真实正确结论），但 `analyzeProcurement` 无条件 `setStep(5)`，而步骤 5（方案审批）和步骤 6（PO 草稿）面板都要求 `plan.net_requirement.has_shortage` 才渲染 → 页面上没有任何按钮可以推进到步骤 7（跟单质量）。

**已修复**（`frontend/src/RealBusinessPage.tsx` 的 `analyzeProcurement`，约 353-362 行）：

```tsx
setPlan(result);
if (result.net_requirement.has_shortage) {
  setSelectedOptionId(result.recommended_option_id ?? result.supplier_options[0]?.option_id ?? "");
  setStep(5);
} else {
  // 库存充足无需采购：跳过方案审批与 PO 草稿步骤，直接进入跟单质量
  setStep(7);
}
```

步骤 5/6 面板本身已有 `has_shortage` 守卫（`step === 5 && plan && plan.net_requirement.has_shortage`），因此跳过时不会显示空审批面板。`npm run build` 已通过。

**待办**：用 100 件（NO_SHORTAGE 路径）和 2000 件（缺料路径）各走一遍浏览器流程复验；stepper 会把跳过的第 5/6 步显示为已完成态，如需精确显示"已跳过"可再优化（非阻塞）。

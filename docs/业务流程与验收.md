# 业务流程说明：汽车零部件工厂四智能体（真实 ERP/MES 版）

更新时间：2026-10-14（本次更新 PPAP 流程）。本文记录已在本地 Docker 部署的 ERPNext 与 OpenMES 上验证过的操作路径。文中的订单号、事件号、数量和截图文件名来自历史验收记录，运行前必须在本机重新查询，不能直接当作当前固定数据。事件去处置联动和当前复核边界以 `docs/handoff_2026-10-01_event_disposal_and_stabilization.md` 为准。

## 验收前准备（约 3 分钟）

1. 一键启动并预检（幂等，重复运行安全）：

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\start_app.ps1
   ```

   全部预检项（后端/OpenMES/ERPNext/身份/DeepSeek/写入令牌）显示绿色"通过"再开始。

2. 打开 <http://127.0.0.1:5173/>，确认顶部显示"ERPNext + OpenMES 真实连接"。
3. 登录项目账号：进入"系统连接" → "项目账号"，使用根目录 `.env` 中的 `PROJECT_AUTH_USERNAME` / `PROJECT_AUTH_PASSWORD` 登录。顶部应显示当前项目操作人；项目账号负责审批身份和操作审计。
4. ERPNext/OpenMES 的账号和 API 凭据由后端服务读取配置文件，不需要在页面中分别登录。普通写入不要求填写高级联调令牌；该入口仅用于维护人员手工排查认证问题。

## 先选择本机记录

验收前不要假设作者电脑上的订单号、工单 ID 或事件号仍然存在。推荐先在页面的“生产跟单”中打开“全厂跟单”，从当前可见的未完工工单中选择一条；如果要验收新电脑导入的数据，优先选择 `TEST_WO_PAGE_00023`、`TEST_WO_PAGE_00024` 或 `TEST_WO_PAGE_00025`。然后把页面显示的订单号替换到下面示例问题中的 `[当前订单号]`。

如果本机没有这些 `TEST_` 记录，先回到 [`部署指南.md`](部署指南.md) 完成产线、主数据和安全种子，不要手动编造数字 ID。历史记录编号只用于说明曾经验证过哪条路径。

## 业务流程 A · 动态协同（先讲"没写死"）

切换到"协同问答"页签，依次问两句，指着调用链说明**同一入口、不同问题、不同调用链**：

- `"[当前订单号] 什么时候能做完？"` → 2 步链（查订单关联 → 跟单进度）。
- `"[当前订单号] 为什么还不能发运？"` → 4 步链（+质量包 + 发运门禁）。

要点：回答里每个数字都来自真实接口，调用链每步有 skill、参数、耗时、记录编号。

## 业务流程 A2 · 任务型多轮会话（P0：上下文沿用 + 追问 + 确定性指令）

在"协同问答"页签连续对话（默认页签），同一会话内第二轮起会自动沿用上一轮上下文：

1. 问 `"[当前订单号] 缺料了怎么办？给我几套方案"` → 回答上方显示"当前沿用订单=…"（上下文回显条，用户可纠正）。
2. 追问 `"数量改成 3000"` → **秒级、不走大模型**：沿用客户/物料/交期重新只读报价（新 QUO 编号、未审批），下方红色块列出旧报价/采购方案/MES 工单"需要重新确认"；明确说明"没写入 ERP、没自动审批"。
3. 再说 `"选第二个方案"` → 按方案卡片展示顺序映射稳定 option_id（快照保存），提示"选择确认≠执行，写入仍走审批门禁"。
4. 换新话题前点「新会话」清空上下文；信息不足时系统先追问（缺什么/为什么/补充后调用哪个智能体），不猜测。

说明：原始消息与中间工具数据默认保留 90 天（`ASSISTANT_RETENTION_DAYS` 可配）；审批/方案/写入/回读证据永久保留；OpenMES 会话令牌过期后系统自动重登（无需重启）。

## 业务流程 B · 速率 ETA（真实速率或如实缺数，可现场报工）

- 问 `"[当前订单号] 什么时候能做完？"` → 如果当前工单有报工记录，回答可含 `RATE_BASED`；页面应同时显示实测速率、剩余数量和依据记录。`RUN-COORD-1F88B4AF6609` 只是历史证据编号。
- 对照 `"WO-2026-001 什么时候能做完？"` → 如实回答数据不足（0% 进度、无报工记录），**不用交期或固定天数编造**。
- **现场报工（新）**：订单流程页签走任意新订单到第 8 步，跟单面板下方"报工（需人工审批）"填本批数量 + 实际耗时 → 确认后 ①建立报工审批（RPT-xxx）→ ②人工批准 → ③ OpenMES 官方报工链路（建批次→开工→完工带实际耗时）→ 回读验证；进度与 ETA 自动刷新为 `RATE_BASED`。真实验证记录：工单 id=12 报工 100 件/20 分钟 → 速率 300 件/小时、ETA 现场算出（`RPT-415078956178`，自动批次号 `LOT-0B24E68049E0`）。
- 说明：重复报工有幂等保护（同批次号命中直接返回，不重复写入）；无工艺快照步骤的工单会如实拒绝报工（提示补 OpenMES 工艺模板），不做伪造数据。

## 业务流程 C · 缺料方案对比 → 双审批 → ERP 草稿

1. 问 `"[当前订单号] 缺料了怎么办？给我几套方案"` → 查看本机真实供应商价格和交期生成的方案卡片；`PROC-5585148630C1` 只是历史测试编号。
2. 选一张卡"选择此方案并起草 PO（需人工确认）"→ 确认面板（已审批过的报价会自动带出双审批线）→ 人工填审批人确认 → 两笔审批号 + PO 草稿号回显，ERPNext `docstatus=0` 回读确认。
3. 追问 `"方案批准了吗？PO 生成了吗？"` → 协调者查到最新状态，闭环联动。

注意：审批/草稿有幂等保护，重复点击不会重复写 ERP。

## 业务流程 D · 质量待办（MRB）→ NCR 处置写回（真实写入，可现场登记）

1. 切换到"质量中心"页签：查看跨工单未关闭问题队列，数量和超期状态以本机页面为准；页签上应显示待办数徽标。
2. 选择一条未关闭问题，点"去处置" → 自动切换到"订单流程"页签，跳到关联工单的 NCR 操作面板并高亮。
3. 已完成的真实验收记录（可现场复述）：处置方案 `返工 rework`、不合格数量 1800、根因/遏制措施已填 → 审批号 `QDISP-1BC2B3498AAE` → 写回 OpenMES → `DISPOSITION_RECORDED · 回读已验证`，关闭前置条件五项全部满足。
4. **现场登记质量问题（新）**：第 8 步质量面板下方"登记质量问题（需人工审批）"→ 选 OpenMES 真实问题类型（11 类下拉，如 Material Defect·HIGH）+ 填标题 → 确认后 ①建立登记审批（QISS-xxx）→ ②批准 → ③ OpenMES `POST /api/v1/issues` 真实创建 → 回读验证；质量数据自动刷新，新 NCR 立即出现在上方列表和全厂待办，**当场即可走处置三步闭环**。真实验证记录：工单 id=11 登记"制动盘端面跳动超差（现场登记验证）"（`QISS-8B341F69A022`，issue id=3，保留 OPEN 供现场处置验收）。
- 说明：重复登记有幂等保护（同工单同标题的未关闭问题命中直接返回）。
5. 如需现场再验收处置写入：选一条新处置（人工选择，不自动推断）走"① 建立处置审批 → ② 批准 → ③ 写回"。
6. 说明：处置后 issue 仍留在待办（RESOLVED+已登记处置）；"关闭"链路（建立关闭审批→写回）具备但验收中不执行，避免把待办清空。

## 业务流程 D2 · 质量异常自动协同（P1 事件协作）

登记质量问题后系统自动跨智能体协同（质量中心页签下方"协同事件"面板）：

1. 第 8 步"登记质量问题（需人工审批）"走完三步（审批→批准→写回 OpenMES）后，**自动产生一条协同事件**（编号 EVT-…）。
2. 切到"质量中心"页签 → "协同事件（自动协作）"面板：点"查看协同结论"展开三维度只读分析——质量影响（未关闭问题/门禁）、生产交期（完成率/ETA 口径）、供应商风险（真实反查报价与采购方案），数据缺口如实标注。
3. 失败的事件可"重试协同"（上限 3 次）；点"人工接管"停止自动协同并留痕操作者——处置仍走审批门禁（接管≠已处置）。
4. **去处置/去处理**：按事件类型点按钮直接跳转对应业务区域——质量事件"去处置"跳工单 NCR 处置面板；缺料事件"去处理方案"跳方案审批视图（带出真实报价与供应商方案）；延期事件"查看跟单"跳工单跟单视图。缺关联编号时明确提示，不猜测跳转。
5. 真实验证记录：`QISS-2C4D1245F52E` → issue 4 → `EVT-BC106E127BA2`（接管验收）；`EVT-04B253B5193D`（已完成验收，生产 100%、采购无缺料）。
- 说明：协同全程只读，结论不写入任何系统；未被人工接管的同一事实不重复触发，人工接管后允许按 `#N` 后缀产生新的协同事件。

## 业务流程 D3 · 缺料/延期自动协同（P1 事件扩展）

- **缺料事件**：走一次含缺料的采购分析（如报价 3000 件后"采购分析"）→ "协同事件"面板自动出现"物料短缺"事件：三维度结论（缺料清单+供应商选项 / 推荐方案成本影响 / 关联工单交期影响），全部真实价格记录；未被人工接管的同一缺料事实不重复触发，人工接管后允许按 `#N` 后缀重新产生事件。
- **延期事件**：工单一旦**已过交期且未完成**（事实），跟单查询时自动产生"生产延期"预警事件（未被人工接管时每工单每天一条；接管后同一事实允许按 `#N` 后缀重新触发）；结论如实给出过期天数与完成率，"是否通知客户"需人工决策。
- **临期事件**（规则 at_risk_v1，用户确认 2026-10-02）：工单**距交期 0-3 天且完成率低于 50%** 时，跟单查询产生"生产临期"事件（每工单每天一条，与延期事件互斥——已逾期只报延期）；结论含剩余天数、完成率与规则版本，"是否加急/调整排程"需人工决策。
- 真实验证记录：`EVT-C62C5AE50AA9`（缺料 3 项、成本 +1180 CNY、交期不延期）；延期/临期路径由测试覆盖，当前真实工单无过期且无 3 天内临期数据（系统如实不触发）。

## 业务流程 G · PPAP 编制与内部审核

入口「质量中心 → PPAP 编制」。功能验收选择 TEST 模式，使用明确标识的本地测试资料；列表默认显示正式任务，查找种子时将「任务范围」改为「测试任务」。正式客户提交使用 REAL 模式并另行验收；模式创建后不可切换，测试任务改名也不能作为正式质量文件。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 未登录尝试创建/编制/批准 | 401；无项目会话不能持久写入，无对应角色返回403 |
| 2 | 登录，选择模式并创建明确客户、零件、图纸版本和侧别的任务 | 22个条目适用性待确认；未知模板拒绝，不复制历史业务值；模式不能后改 |
| 3 | 确认适用性；正式任务核对实际关联对象 | 不适用需依据，未确认项阻断批准；左右件输入不可跨任务混用；TEST拒绝真实关联 |
| 4 | REAL请求批量取证；TEST登记本地测试资料；原件勾选对应条目 | REAL保存调用链、实际来源和指纹，OK/EMPTY/ERROR分开；TEST真实取证被拒绝；两种模式的批准包不能互相引用，嵌套引用也核对历史来源 |
| 5 | 确认来源并录入结构化原始数据，再尝试重复添加特性规格 | 未知字段、布尔数值、合格结论及不支持的来源拒绝；复杂样本与子组必须一致；同任务/特性/侧别的不同记录键重复添加被拒绝，原记录不覆盖 |

### PPAP 输入辅助与修订核对

以下检查沿用已存在的 TEST 任务即可；查看、筛选、载入和版本对照均不需要新增真实业务数据。保存与编制仍是由项目会话授权的独立操作。

| 检查项 | 操作 | 预期行为 |
|---|---|---|
| 有来源的字段预填 | 新增产品基础信息；选择同侧检验/MSA/过程研究的已确认特性 | 任务基本信息及允许的编号、单位、规格只填空字段并显示来源；多候选需选择，重复或矛盾规格不用于预填；测量来源仍单独填写 |
| 人工值与明确空值 | 修改建议字段、清空字段或确认 `null`，切换特性及侧别 | 不覆盖人工输入或明确空值，不从其他侧别带入规格和测量；识别不自动保存 |
| 原始数据表格 | 载入已有 MSA、过程样本和子组；按实际方案新增行 | 显示实际轴、顺序和子组边界；无固定方案默认值，不重排或补造数据；空格为缺测 `null`，非法数值修正前不能保存 |
| 缺项筛选与定位 | 在未编制或有缺项的任务中筛选阻断、条目和岗位，再点「去补充」 | 实时发现和持久未处理问题分别统计；明确位置才提供补录入口，原记录的键、来源、侧别和 `null` 保留；规则或未知位置说明待确认原因 |

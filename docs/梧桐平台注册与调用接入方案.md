# 梧桐平台注册与调用接入方案

核对日期：2026-10-16。本文记录接入范围、代码现状、实施条件和验收方法；不代表智能体已经注册、审核通过或可在平台调用。

后续进度：五个身份已公开回读，六张证书已有用户成功输出；标准运行入口和任务隔离的本地实现已完成。下文第 2 节保留接入改造前的基线，服务器部署、外网和平台调用仍待用户执行。最新操作按 `docs/梧桐服务器接入操作.md` 和 `docs/current_status_and_fix_plan.md` 的最新记录进行。

## 1. 注册范围：一个 Leader，四个 Partner

本项目有五个协作角色。Leader 接收业务问题并选择岗位；四个 Partner 提供岗位能力。角色数量与注册页面的“是否可派生（本体）”不是同一个概念。

| 角色 | 建议注册名称 | 现有实现 | 平台调用目标 |
|---|---|---|---|
| Leader | 汽车零部件协同智能体 | `BusinessCoordinator`；项目内协同问答入口 | 接收自然语言，按需调度岗位，返回答案和调用依据 |
| Partner | 汽车零部件报价智能体 | `/aip/quotation/rpc` | 报价相关的真实资料查询和分析 |
| Partner | 汽车零部件采购智能体 | `/aip/procurement/rpc` | 物料、供应商及采购相关查询和分析 |
| Partner | 汽车零部件生产跟单智能体 | `/aip/tracking/rpc` | 进度、交期和发运前置条件查询 |
| Partner | 汽车零部件质量文档智能体 | `/aip/quality-document/rpc` | 质量问题、PPAP 状态、缺项、取证计划及版本查询 |

这五个服务均为直接提供服务的实体时，“是否可派生（本体）”选“否”。Leader 调度 Partner 不等于批量派生实例；若以后需要派生实例，应另行设计实体生命周期。

首期平台能力沿用真实只读目录。PPAP 编制、资料确认、审核、归档及 ERP/MES 写入仍由已登录项目用户走原有任务和人工审批流程。平台的智能体证书不能替代项目人工身份。

## 2. 注册前核对的代码基线（接入改造前）

1. 四个 Partner 已使用 ACPs SDK 的 JSON-RPC 处理器，不是只有静态 ACS。服务路由按 URL 选择具体岗位。
2. Leader 目前通过 `/api/real-orders/assistant/ask` 及项目自定义 SSE 提供问答，没有独立的 AIP RPC 服务或 ACS。项目 SSE 不能直接声明为 ACPs AIP STREAM。
3. 四份现有 ACS 含 `TBD-*`、`localhost` 和示例提供方；运行身份为 `local-*`。这些文件可供开发核对，不能当作正式平台注册材料。
4. 当前 RPC 关闭身份绑定；ACS 中的 API Key/mTLS 声明不能证明路由已经执行认证。
5. 当前 Partner 实际使用 `TextDataItem.text = 技能ID|JSON`。解析器虽有结构化技能分支，但依赖 SDK 2.2 数据项中不存在的 `kind/name` 字段，尚不能将该分支视作已兼容。普通自然语言也会被当作技能 ID，直接登记地址不能解决平台自然语言调用。
6. SDK 的 `TaskManager` 是进程共享内存。现有代码没有按岗位和原始调用方核验任务所有权；公开服务需防止跨身份读取、取消和完成任务。
7. 本地实际安装了 SDK 2.2.0，项目 `backend/pyproject.toml` 尚未声明该依赖。服务器环境应显式安装与锁定经过验证的版本。

主要代码位置：

- `backend/app/aip/__init__.py`：四岗初始化、路由和能力目录。
- `backend/app/aip/aip_agent_service.py`：输入解析、任务执行、RPC 注册。
- `backend/app/aip/aip_agent_client.py`：岗位调用客户端。
- `backend/app/aip/generate_acs.py`：当前开发 ACS 生成器。
- `backend/app/services/coordinator.py`：Leader 及只读技能目录。
- `backend/app/main.py`：项目问答、登录、审批和业务写入边界。

## 3. 官方接入顺序与注册资料

首次注册提交真实名称、能力、提供方与协议字段，取得审核结果和正式 AIC 后，再申请相应证书、部署服务端点并验证调用。**当前线上自动准入已明确要求至少一个有效 Endpoint 或 webAppUrl**，见用户本轮真实驳回意见。旧版公开创建/提交代码允许空端点，不足以证明当前自动审核会接受缺少全部入口的材料；本次通过实测网页地址补齐 webAppUrl。服务实际可调用的验收与注册申请分开处理，不能将证书部署设为获取 AIC 前的循环条件。

不能复制示例 AIC，也不能自行填写 `verifiedFields` 作为已认证的声明。示例带注释，不能直接当作严格 JSON 提交；示例的流式、通知和消息队列能力也不能照抄。

正式资料需确认：

- 注册主体及可提供的真实公开资料；平台认证和必填要求以线上表单为准，未知的可选资料先省略。
- 所选公网 IP 或域名的管理权限和归属资料；使用域名时再核对域名备案或注册资料。
- 五个服务的对外地址与长期运行方式。网页的 5173 地址不是自动可用的 AIP 地址。
- 梧桐注册账号处于可使用状态；账号登录、验证码等由用户在平台完成，不通过聊天传递凭据。

提交后若平台仍在审核，应记录为“待审核”。未取得 AIC 或证书时，不能标记为平台调用已完成。

## 4. 五个正式身份的服务部署

协议 02.02 的严格绑定不仅核验请求里的 AIC，还需核验 TLS 证书中的 AIC。作为被调用方，服务端证书与其对外身份应对应；主动调用另一个智能体时使用适合 clientAuth 的证书及信任链。平台文档中的 clientAuth 申请示例不能替代被调用服务所需的 serverAuth 配置。

**五个 URL 路径共用一个普通 TLS 证书，不等于五个独立正式身份。** TLS 握手早于 HTTP 路径。五身份部署应在以下方式中根据域名和现有服务器配置确定一种：

- 五个独立 TLS listener，分别使用各自身份的证书；端口和地址需确认。
- 五个可区分的 SNI 域名，各自证书与身份对应，前置层保留真实 TLS 身份。

SDK 提供 `AipPeerCertH11Protocol` 和 `AipPeerCertificateMiddleware` 从真实连接提取证书身份。不得把外部请求任意填写的 `X-Client-*` 头当作证书身份。

这些部署选择依赖证书及服务器入口条件。选择公网 IP 时可采用同一 IP 上各身份独立的 TLS listener，具体端口在服务器配置后确认；使用 SNI 方案才依赖不同主机名。不能先暴露无认证接口，再以 ACS 声明代替实际认证。

## 5. 实施阶段

### A：注册前准备

- 确认五个角色及其真实可调用能力，核对主体、域名和部署方式。
- 补齐 Leader AIP 入口；适配自然语言和结构化输入，岗位调用保持各自能力范围。
- 实现任务所属服务、调用方 AIC、session 和 task 的一致性校验，拒绝跨身份任务操作。
- 增加正式身份与证书配置校验；获批后的运行部署遇到占位 AIC/地址或能力与运行时不符时明确拒绝发布。初次注册材料中尚未分配正式 AIC 是正常状态，不以此阻止申请。
- 明确 SDK 依赖及服务器启动要求；先完成本地协议与权限回归。

### B：平台注册与证书

- 从真实资料生成五份严格 JSON，用户可检查名称、描述、提供方和端点。
- 通过已登录的平台注册；记录每项实际申请状态及平台分配的 AIC。
- 审核通过后申请合适用途的证书。证书私钥、登录会话和 EAB 不写入文档、聊天或 Git。

### C：服务器部署与平台调用

- 沿用现有业务数据库、文件目录及人工审批边界部署接入服务。
- 逐一验证五个身份的 HTTPS、证书链、AIC 绑定、JSON-RPC 任务生命周期和调用方隔离。
- 从梧桐实际调用 Leader 和四个 Partner，核对真实结果与调用依据。
- 按平台 AMP 要求上报调用记录：access 的 `correlationId` 对应 taskId；消息配对使用真实 messageId 与 send/receive 事件。不得上传请求凭据。

## 6. 接入验收

| 编号 | 需要的证据 |
|---|---|
| WT01 | 五个注册项各自的正式 AIC 和真实审核状态；草稿与已批准状态分开记录 |
| WT02 | 五份 ACS 的技能与实际运行目录一致，URL 可达，无占位提供方、示例 AIC 或未实现的能力声明 |
| WT03 | 平台自然语言请求得到正常 AIP 任务与结果；结构化输入也能按契约执行 |
| WT04 | Leader 按问题选择岗位；结果带真实来源，失败或数据缺失不伪造为成功 |
| WT05 | mTLS 与入站/出站 AIC 校验有效；错误证书、错误调用身份明确拒绝 |
| WT06 | 不同岗位或调用方不能读取、取消、完成对方任务；重复请求及服务重启行为明确 |
| WT07 | 原项目登录、人工审批、PPAP 本地写入及 ERP/MES 写回规则回归通过；平台通道未变成写入绕过入口 |
| WT08 | 平台检索、真实调用和 AMP 调用配对有可核对记录；构建成功或 HTTP 健康检查不替代此项 |

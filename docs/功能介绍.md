# 功能介绍：汽车零部件工厂四智能体协作平台

> 更新时间：2026-10-02。本文是**面向使用者的功能总账**：系统有什么功能、在哪个页面、怎么用、背后的规则是什么。开发状态与修复记录见 `docs/current_status_and_fix_plan.md`，演示操作剧本见 `docs/demo_script.md`，部署见根目录 `README.md`。

---

## 1. 这是什么系统

一家汽车零部件工厂里的**四个 AI 智能体**（报价 / 采购 / 跟单 / 质量）在**真实 ERPNext + OpenMES** 业务数据上协作的平台：从客户询价到报价审批、缺料采购、工单跟单、质量处置、发运门禁的完整闭环。

```
浏览器 http://127.0.0.1:5173  ← 使用者操作界面
   │
后端  http://127.0.0.1:9000  ← 智能体协调 + 审批门禁 + 业务库（默认 SQLite）
   ├── ERPNext  http://127.0.0.1:8080   客户/物料/BOM/价格/库存/销售与采购草稿
   ├── OpenMES  http://127.0.0.1/       工单/批次报工/质量 NCR/检验/发运
   └── DeepSeek                        驱动协同问答（未配置时问答如实返回 503，其余功能不受影响）
```

**四个智能体的分工**

| 智能体 | 职责 | 典型技能（可在调用链中看到） |
|---|---|---|
| 报价 Agent | 算成本/毛利/建议单价/交期估算、缺料成本影响评估 | `quotation.analyze_real`、`quotation.assess_cost_impact` |
| 采购 Agent | BOM 展开算净需求、找真实供应商价格与交期、生成采购方案 | `procurement.analyze_real`、`procurement.get_real_plan` |
| 跟单 Agent | 订单-工单关联、生产进度、按实测报工速率推算 ETA、交期影响 | `tracking.lookup_order_link`、`tracking.track_real` |
| 质量 Agent | 质量资料包、质量门禁、NCR 队列、发运门禁 | `quality.package`、`shipping.gate_check` |

**三条铁律（贯穿所有功能）**

1. **数据真实**：一切数字来自真实系统接口并标注来源与记录编号；缺数据/连不上**如实报错**，不回退 Mock、不编造。
2. **写入门禁**：任何写真实系统的操作必须走 **人工审批 → 写回 → 回读验证 → 幂等** 四步；AI 只读不写，"草稿级写入"（docstatus=0）也需审批后才创建。**审批与写入必须以登录的审批账号身份执行**——未登录时审批/写入接口直接返回 401，不会以服务端集成账号名义替人审批（2026-10-02 起强制）；报价分析等只读查询 + 本地留痕操作无需登录。
3. **全程留痕**：每次智能体调用记录 skill、参数、耗时、结果摘要（`RUN-…`），审计页可追溯。

## 2. 页面功能地图（左侧导航 8 个模块）

### 2.1 AI 协同问答（默认主入口）

- **一句话提问**：协调者自动判断要查什么，动态调度智能体组合。同一个入口，不同问题产生**不同长度的调用链**（例："什么时候能做完"≈2 步链；"为什么还不能发运"≈4 步链，多查质量包与发运门禁；"缺料怎么办"≈13 次调用跨 3 个智能体）。
- **调用链留痕**：每步显示智能体、技能名、入参、耗时；失败步骤红色原样展示；整轮有 `RUN-COORD-…` 记录号。
- **多轮上下文沿用**：同一会话内自动沿用客户/物料/订单/工单/数量/交期，回答上方回显"当前沿用 …"，可直接说"改成 XX"纠正。
- **确定性指令（秒回、不走大模型）**：
  - `数量改成 3000` → 沿用客户/物料/交期重新只读报价（新 QUO 编号、未审批、不写 ERP），旧报价/方案/工单标记"需要重新确认"；
  - `选第二个方案` → 按方案卡片展示顺序映射稳定 option_id 并存快照；方案基于旧数量时**拒绝选择**并引导重新分析。
- **追问澄清**：信息不足先反问（缺什么/为什么/补充后调用哪个智能体），不猜测。
- **新会话语义**：点"新会话"开启全新业务任务——首轮**不自动带入**页面当前工单/订单（防止旧对象污染），第二轮起恢复正常策略；用户自己输入的编号永远优先。
- **连续聊天**：历史轮次沉入消息列表（输入框固定在上方，消息区内部滚动并自动滚到最新）；切到其他模块再回来记录仍在；**刷新页面后按会话号自动恢复**。
- **历史会话切换**：问答页可查看/切回之前的会话（含会话首句与时间），像聊天软件的聊天记录切换。<!-- 历史会话切换：2026-10-02 新增 -->
- **方案卡片执行闭环**：缺料方案卡显示真实供应商总价/交期/成本影响/毛利变化与规则版本（`lowest_total_cost_v2`），点"选择此方案并起草 PO"→ 确认面板 →（报价未审批时自动带出双审批线）→ 人工批准 → PO 草稿写入 ERPNext 并回读。
- **回答分层**：结论/关键事实/下一步首屏呈现；调用链、质量影响明细、数据缺失明细默认折叠，点击展开，不截断事实。
- **业务跳转**：回答携带对象编号时显示"查看该工单跟单 / 打开该方案审批 / 打开该报价"按钮，点击**跳到对应业务模块并自动定位打开对象**。

### 2.2 业务总览（驾驶舱）

- 四张 KPI 卡：**报价待审批 / 方案待审批 / 质量待办 / 缺料·风险事件**，点击直达对应模块（待审批数为**全局口径，含历史记录**）。
- **需要处理**：未完成、未被接管的协同事件按时间排列，按事件类型显示"去处置/去处理/查看跟单"，点击携带事件编号定位打开对象。
- **最近业务链**：最近 5 次智能体真实调用（谁、干了什么、成功失败）。
- **AI 协同入口**：输入问题点"去提问"，问题带到问答页填好待确认发送。

### 2.3 销售与订单（8 步链 ①-③）

完整订单主线为 8 步：①报价分析 → ②报价审批 → ③ERP 草稿 → ④采购分析 → ⑤方案审批 → ⑥PO 草稿 → ⑦跟单质量（工单下达）→ ⑧发运门禁。每个业务模块只显示本阶段步骤条，完整 8 步收进折叠；**步骤条高亮与"已完成"提示由已加载业务对象证明**，跳转残留不会伪装进度。

- ①**报价分析**：选客户/物料/数量/交期 → 从 ERPNext 读 BOM、价格表、库存 → 生成 `QUO-…` 报价（成本明细、毛利率、BOM 结构全部带 ERP 编号）。两个口径要分清：
  - **库存状态**指**成品**库存是否够本单（"需生产"= 成品不足、需排产）；采购页的**库存充足**指 **BOM 原材料**是否够用——两者对象不同，并不矛盾。
  - **预计交期**（需生产时）= 距该物料在 OpenMES 里**最早一张未完成工单到期日**的倒计时（卡片下方标注依据工单号），**不随报价数量变化**，仅作排程参考；按数量和实测速率的动态产能估算在跟单侧（RATE_BASED ETA）。没有任何排程数据时如实显示"数据缺失，需补录 ERP 交期数据"，绝不套固定公式。
- ②**报价审批**：人工批准/驳回 → 生成 `approval_id`，状态 APPROVED。AI 算价、人批（**需登录审批账号**）。
- ③**ERP 草稿**：创建 ERPNext 销售订单草稿（docstatus=0）→ 回读验证（`read_back_verified`）。未审批不能创建；幂等，重复点不会生成两条。
- **返回初始状态**：页面右上"↺ 返回初始状态（开始新订单）"——只清空页面流程状态开始下一笔订单；已创建的审批记录、ERP 草稿与审计留痕仍保留，可在「审批与审计」查看。

### 2.4 采购与缺料（8 步链 ④-⑥）

- ④**采购分析**：基于已审批报价做 BOM 展开 + 真实库存 → 缺料清单（毛需求/可用库存/净缺）；无 BOM 时**如实阻断**（EVALUATION_BLOCKED，提示补录 ERP，不伪造"无缺料"）。
- ⑤**方案审批**：真实供应商方案对比（单一供货 vs 分单采购），含覆盖项、总价、交期、成本影响、质量风险与推荐理由 → 人工选择并批准。
- ⑥**PO 草稿**：创建 ERPNext 采购订单草稿并回读确认。
- **两类订单别混淆**：**销售订单**（`SAL-ORD-…`，成品出库方向，驱动 MES 工单生产成品）和**采购订单**（`PUR-ORD-…`，原料补货方向，向供应商买缺料）是同一笔业务的两张不同单据。生产跟单页"下达工单"为**销售订单**建 MES 工单；采购订单的到货日期影响的是**原料齐套时间**（体现在跟单的交期影响评估里）。
- 无报价/方案对象时显示明确空态（"尚未选择报价或采购方案"），提供"去销售与订单 / 去审批与审计（待审批方案）"入口；同样提供"返回初始状态"工具条。
- **继续已有订单**（2026-10-02 用户建议）：销售与订单空态可从最近 20 条历史报价中**选择载入**（显示客户/物料/数量/状态/ERP 草稿号）；采购与缺料空态可从最近 20 条**采购方案**中选择载入（显示所属报价/审批状态/缺料情况）——跟单页的"全厂跟单"同理，三个模块都支持跨历史记录继续操作，而不是只能开新头。
- **跨订单防护**：生成新报价时自动清除旧的采购方案状态；若加载的方案与当前报价不同单，采购页会显式提示"不是同一笔订单"并提供"为当前报价重新分析 / 返回初始状态"。

### 2.5 生产跟单（8 步链 ⑦-⑧ + MES 完工数据）

- **全厂跟单（跨订单）**：生产跟单页顶部可选择**任意未完工工单**（按交期排序，标注关联的 ERP 订单与交期）直接查看进度、质量与发运门禁——不必先在销售流程中走完该订单；发运门禁中的报价审批状态由系统按工单关联的 ERP 订单号反查，不猜测。流程内的"当前订单"下拉与全厂跟单互不影响。
- **工单下达**（无关联工单时的主操作，置顶呈现）：点"下达工单到 OpenMES"→ 展开确认单（列出①建立审批 ②人工批准 ③创建工单+回读）→ 点"确认下达"三步自动执行；order_no 由 ERP 订单号派生，customer_order_no 精确关联并回读验证，成功后工单自动出现在下拉框。**前提：需登录审批账号 + 本地写入令牌**（写入令牌在"系统连接 → 高级联调设置"填一次，值对应根目录 `.env` 的 `REAL_WRITE_API_TOKEN`；缺令牌会如实报"真实系统写入令牌无效"）。失败时提供"重置后重新下达"。
- **跟单视图**：进度（工序/批次/合格数）、质量资料包、发运门禁三面板；ETA 两种口径——有报工记录时 **RATE_BASED**（实测速率推算），无记录时**如实说数据不足**，不拿交期日期充数。
- **发运门禁（判定，非执行）**：三重门禁全部通过才显示"可以发运"——报价/订单审批、质量门禁（未关闭问题=0）、完成率≥90%。**阻塞行自带"去处理"入口**：报价审批 ✗ → 直达关联订单的报价审批（订单无报价记录时如实提示，不伪造入口）；质量门禁 ✗ → 跳质量中心。OpenMES 无订单级质量放行/发运执行 API，系统到"判定"为止，实际发运在交付环节执行（诚实边界，不提供假发运按钮）。
- **现场报工（需人工审批）**：填本批数量 + 实际耗时 → 建立报工审批（`RPT-…`）→ 人工批准 → OpenMES 官方报工链路（建批次→开工→完工带实际耗时）→ 回读验证；进度与 ETA 自动刷新。重复报工幂等；无工艺快照步骤的工单**如实拒绝**并提示补模板。
- **MES 完工数据**（二级视图）：全厂完工只读看板。

### 2.6 质量中心

- **跨工单质量待办**：未关闭问题队列（严重度、已报告天数超期标红；页签有待办数徽标）；"去处置"跳到对应工单的 NCR 面板并高亮。
- **登记质量问题（需人工审批）**：选 OpenMES 真实问题类型（11 类）+ 标题 → 登记审批（`QISS-…`）→ 批准 → OpenMES 真实创建 → 回读验证；同工单同标题幂等。
- **NCR 处置 → 解决 → 关闭三态**（三个独立审批链，缺一不可）：①**处置**（人工选 scrap/rework/return_to_supplier/use_as_is + 根因 + 遏制措施 → `QDISP-…` 审批 → 写回回读 `DISPOSITION_RECORDED`）；②**解决**（处置写回 ≠ 问题解决——让步接收也不例外：填解决说明 → 解决审批 → resolve 写回，OpenMES 的 issue 状态翻成 RESOLVED，关闭前置条件"问题已解决"才满足）；③**关闭**（五项前置条件全绿后：关闭审批 → 写回 → issue CLOSED）。质量门禁看的是"未关闭问题数=0"，全部关闭后发运门禁的 can_ship 才可能为 true。
- **缺料类 NCR 的特殊口径**：NCR 处置出口只有 OpenMES 上游定义的四种（报废/返工/退供应商/让步接收），**不含"补库存"**——补库存的业务动作在「采购与缺料」模块（缺料分析 → 供应商方案 → PO）。缺料类问题（Material Shortage）的 NCR 卡片会显示引导块并提供跳转入口；物料到货后该 NCR 一般按"让步接收"关闭，并把采购单号写进遏制措施留痕。
- **协同事件（自动协作）**：登记质量问题/缺料/延期/临期发生后**自动产生协同事件**（`EVT-…`），三维度只读分析（质量影响 / 生产交期 / 供应商风险），数据缺口如实标注；失败可"重试"（上限 3 次）；"人工接管"停止自动协同并留痕。事件类型：
  - `quality_issue_raised` 质量异常 → 去处置跳 NCR 面板；
  - `material_shortage` 缺料 → 去处理方案跳方案审批视图；
  - `production_overdue` 延期（已过交期未完成，每工单每天一条）；
  - `production_at_risk` 临期（距交期 0-3 天且完成率 <50%，与延期互斥）。
  - 同一事实未接管不重复触发；接管后允许按 `#N` 后缀重新产生。

### 2.7 审批与审计

- **待审批区块**：报价 / 采购方案 `PENDING_APPROVAL` 列表，可定位打开对应对象审批。
- **Agent 运行记录**：每次智能体调用的输入、结果与耗时全程留痕，可追溯。
- 能力目录治理：`/aip/capability-catalog` 汇总 18 项技能的 `read_only / requires_approval` 声明（含全厂库存总览 `procurement.inventory_overview`），协调者只能调用目录内白名单技能。

### 2.8 系统连接

- **数据连接**：ERPNext / OpenMES 真实探测状态（"已连接"来自真实请求，不是配置了就算）。
- **审批账号**：OpenMES 账号密码登录（普通操作只需要这里），显示当前审批账号 `admin（OpenMES）`；会话 15 分钟 TTL，**页面实时倒计时**，临期黄条提示"剩余 X 分 X 秒"；登出只清浏览器会话不吊销上游令牌。
- **高级联调设置**（默认折叠，与审批账号**二选一**，仅部署/开发联调用）：手工 Bearer 会话、本地写入令牌 `X-Real-Write-Token`（服务端 `REAL_WRITE_API_TOKEN` 门禁，MES 写入类接口需要）。

> 另有一组 **Mock 演示页签**（场景与回放/协同驾驶舱等，合成数据），在 `APP_ADAPTER_MODE=real` 下整组隐藏，与真实业务隔离。

## 3. 会话与数据保留规则

| 数据 | 保留策略 |
|---|---|
| 问答原文（问题+回答） | 业务库 90 天（`ASSISTANT_RETENTION_DAYS` 可配），到期惰性清理 |
| 业务任务上下文/摘要/状态 | 永久 |
| 审批、方案、写入与回读证据 | 永久（审计要求） |
| 智能体运行记录 | 90 天 |
| OpenMES 登录会话 | 15 分钟 TTL（上游 Sanctum 安全设计），过期重新登录即可 |
| 浏览器 sessionStorage（会话号/令牌） | 关闭浏览器标签即清；不写入项目文件与审计 |

- 点"新会话"= 开启新业务任务（旧对话数据仍在库里，可通过问答页"历史会话"切换回去查看）。
- 问答回答由 DeepSeek 汇总**真实工具结果**生成，措辞每次略有差异，但数字全部来自工具返回。

## 4. 诚实性边界（系统"不会做什么"）

- **SN 级单件追溯**：OpenMES 无对应 API，页面如实标注 `NOT_SUPPORTED` / 数据缺口，追溯仅到批次（lot）维度。
- **订单级质量放行**：OpenMES 无对应 API，明确不支持。
- **数据缺失**：无 BOM / 无价格表 / 无检验记录时如实报 `EVALUATION_BLOCKED` / 列出缺口，不编造结论。
- **Mock 隔离**：真实模式下旧 Mock 路由返回 404 `mock_surface_disabled`；测试数据一律 `TEST_` 前缀。
- **写操作不自动执行**：问答与智能体全程只读；所有写入停在人工审批门禁，AI 不能代批。

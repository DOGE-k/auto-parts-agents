## 平台调用失败怎么定位（叮当显示「技能执行失败」）

平台页面上只显示项目代码里的一句固定文案「技能执行失败，请检查服务日志」，真实异常只写进服务器日志。按下面顺序定位：

1. 看日志里真实的异常类型：

```bash
tail -n 120 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/leader.log
tail -n 120 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/quotation.log
tail -n 120 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/tracking.log
```

2. 若出现 `UnicodeEncodeError: 'ascii' codec can't encode characters in position 7-9`，说明运行时生效的 `DEEPSEEK_API_KEY` 含非 ASCII 字符（`position 7` 起就是密钥内容）。

   注意：这不一定是 `.env` 的问题。旧版启动脚本不传 `env`，进程会继承启动 shell 的环境变量，而 `load_dotenv(override=False)` 又让已存在的变量优先——所以 `.env` 改对了也可能不生效。按下面确认：

```bash
cd /home/ubuntu/apps/auto-parts-agents
grep -c '\[密钥\]' scripts/start_wutong.sh     # 0 = 还是旧脚本
grep -n '^DEEPSEEK_API_KEY=' .env               # 只看变量名，别贴值
```

   新版启动脚本会在起进程前打印 `[密钥] 来源=dotenv|shellEnvironment 长度=... ASCII=...`，非 ASCII 直接拒绝启动并写明来源。用 `stop` → `unset DEEPSEEK_API_KEY` → `start` 可确保子进程只采用 `.env` 的值。

3. 若出现 `IntegrationError`/`IntegrationNotConfigured`，按报错里的集成名称检查对应 ERPNext/OpenMES/DeepSeek 配置。
4. 若出现 `unknown skill` 或 `Caller AIC is not allowed`，检查能力目录 `rejections` 与 `runtime.json` 的 `allowedCallerAics`。

Leader 与四个 Partner 共用同一份 `.env` 和同一套模型调用代码，所以密钥类问题会让所有被调用的节点同时失败，不能只修某一个角色。

## 怎么看日志、怎么停止

查看 Leader 最近 80 行日志：

```bash
tail -n 80 /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/leader.log
```

持续看新增日志：

```bash
tail -n 80 -f /home/ubuntu/apps/auto-parts-agents/backend/data/wutong-runtime/logs/leader.log
```

按 `Ctrl+C` 退出看日志，服务继续运行。其他角色日志把文件名替换为 `quotation.log`、`procurement.log`、`tracking.log` 或 `quality-document.log`。不要粘贴含业务敏感内容的完整日志；定位失败时提供相关错误附近的少量行即可。

停止本脚本管理的五个接入进程：

```bash
bash /home/ubuntu/apps/auto-parts-agents/scripts/stop_wutong.sh
```

停止脚本核对进程所有者、启动时间、完整启动参数，并通过 Linux pidfd 发送信号；过期 PID 不会用于终止其他进程。它不会扫描端口并杀占用者，也不会调用 Docker 或停止原有 9000/5173 应用。

目前这套脚本提供 SSH 断开后继续运行的后台进程管理，没有安装开机自启，也没有配置证书自动续期。用户提供的证书有效期均到 2026 年 12 月 4 日；到期前需按平台流程续期，检查通过后重启接入进程。

# 交接文档：能力目录运行时构建

> 交接对象：下一位负责实现和复核的 AI 或开发者。  
> 项目路径：`E:\competition\汽车零部件工厂智能体开发`  
> 文档日期：2026-10-02  
> 当前状态：**已实施（2026-10-02 下午，见 `current_status_and_fix_plan.md` §3.55）**。本文保留为设计依据与验收标准的原始记录；实施结果（字段盘点结论、回退策略、测试与真实端点验证）以 §3.55 为准。

## 一、先说清楚要改什么

当前系统已经能够“动态选择技能”：协调者会根据用户问题，从 `REAL_SKILL_TOOLS` 中选择需要调用的技能，再通过 AIP 调用报价、采购、跟单或质量文档智能体。

现在的问题是：这份能力目录本身仍然写死在 `backend/app/services/coordinator.py` 的 `REAL_SKILL_TOOLS` 列表里。ACS 生成、AIP 真实技能白名单和协调者工具选择都依赖这份代码内列表。

本阶段要做的是把“能力目录的来源”改成运行时读取已经注册的 AIP/ACS 能力信息，并统一转换为协调者使用的结构化目录。目标不是改变四个智能体的业务逻辑，也不是新增业务技能。

## 二、当前已确认的代码关系

接手者必须先阅读以下位置，不要直接改名或猜接口：

| 位置 | 当前作用 |
|---|---|
| `backend/app/services/coordinator.py` | 定义 `REAL_SKILL_TOOLS`，协调者从这里选择真实只读技能 |
| `backend/app/aip/generate_acs.py` | 当前从 `REAL_SKILL_TOOLS` 生成 ACS 技能描述，避免 ACS 与目录漂移 |
| `backend/app/aip/__init__.py` | AIP 初始化时从 `REAL_SKILL_TOOLS` 生成各智能体的真实技能允许列表 |
| `backend/app/aip/aip_agent_service.py` | AIP RPC 服务注册、技能限制和调用入口 |
| `backend/app/aip/acs/` | 四个智能体的 ACS 能力描述文件，需核对是否为生成产物以及运行时是否读取 |
| `backend/app/main.py` | 注册表配置缺失时已有明确提示，不能把本地目录冒充外部注册结果 |
| `backend/app/runtime/surface.py` | 真实表面与 Mock 表面的隔离边界 |
| `backend/tests/` | 现有 AIP、能力目录、Mock 隔离和协调者回归测试 |

当前架构的事实关系是：

```text
REAL_SKILL_TOOLS（代码内静态列表）
        ├── 协调者选择技能
        ├── AIP 真实表面白名单
        └── generate_acs.py 生成 ACS
```

目标架构应变成：

```text
AIP/ACS 注册信息
        ↓
能力发现与字段校验
        ↓
统一的运行时能力目录
        ├── 协调者选择技能
        ├── AIP 真实表面白名单
        └── ACS 生成或一致性检查
```

## 三、目标能力目录

运行时目录至少要能表达下面这些信息。字段名称不能直接假定，必须先和当前 AIP/ACS 实际返回结构逐项对应：

| 目录信息 | 用途 | 必须确认 |
|---|---|---|
| `skill_id` | 稳定识别技能 | 是否与 AIP RPC 技能 ID 完全一致 |
| `agent_type` / `aip_agent` | 找到所属智能体 | 当前四个智能体的映射关系 |
| `description` | 让协调者判断何时使用 | 是否来自注册信息，是否允许覆盖 |
| 输入 schema | 校验调用参数 | 是否能转换为现有工具参数格式 |
| 输出 schema | 记录预期结果 | 缺失时如何标记数据缺口 |
| `version` | 判断目录和服务是否匹配 | 版本格式和兼容策略 |
| `endpoint` | 找到 AIP RPC 服务 | 是否由注册信息提供，不能拼接猜测 |
| `authority` / `data_source` | 标明 ERPNext、OpenMES 或本地数据来源 | 是否为注册字段还是技能返回字段 |
| `read_only` | 防止协调者越过写入门禁 | 缺失或不明确时应拒绝进入真实目录 |
| `requires_approval` | 标明是否必须审批 | 当前协调者只允许真实只读技能 |
| `source` / `fetched_at` | 追踪目录来源和刷新时间 | 用于日志和故障排查 |

其中 `read_only`、`requires_approval`、数据来源和权限不是装饰字段。只要无法确认，就不能把该技能加入真实协调者目录。

## 四、实施顺序

### 第 1 步：盘点实际注册信息

先只读检查：

1. AIP 服务实际公开的技能 ID、描述和参数结构；
2. ACS 文件或注册接口实际包含的字段；
3. `WUTONG_REGISTRY_URL` 等注册表配置在当前部署中的真实含义；
4. 注册表不可用、超时、返回非法字段时，现有系统希望采用“保留本地已验证目录”还是“真实表面拒绝启动/拒绝调用”。

如果以上任何一项无法从源码、配置或本地真实响应确认，先停下来记录未知项，不要自行发明协议字段。

### 第 2 步：建立统一目录适配层

新增最小的发现/校验层，将 AIP/ACS 信息转换为现有协调者需要的工具结构。建议具备：

- 来源标记：外部注册、AIP 服务、ACS 文件或本地受信任回退；
- 必填字段校验和重复 `skill_id` 检查；
- 智能体、技能、端点之间的一致性检查；
- 只读和审批属性的安全默认值；
- 目录快照和刷新时间；
- 可测试的失败结果，不把异常吞成空目录。

具体类名、模块名和缓存时长由接手者根据现有代码决定，不能为了“动态化”引入另一套平行注册表。

### 第 3 步：逐个替换现有使用方

按以下顺序替换，保持每一步可回归：

1. 协调者工具选择改为读取统一目录；
2. `init_aip_agents` 的真实技能允许列表改为读取同一目录；
3. ACS 生成改为读取同一目录，或者增加目录与 ACS 的一致性校验；
4. 保留 Mock 表面的原有隔离，不得因为运行时发现而把 Mock 技能暴露到真实表面；
5. 保留现有 17 个真实只读技能的行为和稳定 ID，除非有明确的注册信息证据证明 ID 已变更。

### 第 4 步：保留安全回退

回退行为必须在实现前根据当前部署契约确定，但必须满足以下底线：

- 不能把本地静态列表伪装成外部注册结果；
- 不能把注册失败转换成“没有技能”后继续误调用；
- 不能因为注册信息里出现一个技能名称就自动开放写入能力；
- 不能让协调者绕过人工审批调用 ERPNext/OpenMES 写入；
- 注册信息不完整时，至少应拒绝该技能进入真实目录，并留下可读错误。

## 五、测试和验收

必须先补有意义的测试，再修改实现。最低覆盖如下：

1. 注册信息成功读取并生成四个智能体的目录；
2. 目录包含现有真实技能，技能 ID、所属智能体和参数可用于原有协调者调用；
3. 重复技能 ID、未知智能体、缺少输入 schema 或缺少权限属性时被拒绝；
4. 注册表超时、不可达、非法 JSON 或版本不兼容时有明确结果，不返回误导性的空成功；
5. 真实表面只暴露目录中的真实只读技能；Mock 技能仍不能进入真实表面；
6. ACS 与运行时目录在技能 ID、智能体归属和权限属性上保持一致；
7. 既有协调者调用链、事件协作、问答追问和审批门禁不回归；
8. 运行时刷新或重启后，目录来源、版本和时间戳可追溯。

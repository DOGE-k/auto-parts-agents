# 同学电脑真实 ERPNext + OpenMES 复现部署

本文针对“同学在自己的 Windows 电脑上部署一套真实 ERPNext、真实 OpenMES、业务后端和前端，并导入与当前环境相同的演示数据”的目标。它不是把当前电脑的数据库或密钥复制给别人；每台电脑会建立自己的外部系统实例，再用受控种子脚本写入可复现的测试数据。

## 先说清楚能复现什么

- 可以复现：ERPNext + OpenMES 的真实容器、业务后端、前端、真实适配器模式、页面与协同问答链路，以及仓库中明确标记的演示业务记录。
- 不会复现：当前电脑的实时数据库、登录会话、ERPNext API Secret、OpenMES Token、DeepSeek Key、Cookie、证书。它们必须由每位使用者在本机重新创建。
- “真实”指应用确实从本机运行的 ERPNext/OpenMES 读取；种子数据仍是测试数据，不能把 `TEST_`/`DEMO_` 记录描述成真实工厂生产记录。
- 当前仓库没有在干净 Windows 电脑上完成从零到页面的实测，因此在完成一次干净机重放前，只能说“提供复现脚本和步骤”，不能宣称已经验证可一键部署。

## 一条入口命令

在 PowerShell 中进入仓库根目录后运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1
```

脚本会检查 Docker Desktop、Git、Python 3.12/3.13、Node.js 20+ 和 npm；缺少工具时停止并给出安装提示。它会按需克隆以下两个上游仓库到 `services/`（这些目录被 `.gitignore` 排除，不会被提交到本项目）：

- `https://github.com/Mes-Open/OpenMES.git` → `services/OpenMes`
- `https://github.com/frappe/frappe_docker.git` → `services/frappe_docker`

脚本不覆盖已有 `.env`。首次运行会生成：

- 根目录 `.env`：从 `.env.example` 复制，真实凭据留空；
- `services/OpenMes/.env`：从 OpenMES 上游模板复制；
- `services/frappe_docker/.env`：从 `scripts/templates/erpnext.env.example` 复制；
- `frontend/.env.local`：只写入本机后端地址 `http://127.0.0.1:9000/api`。

`.env` 文件均为本机文件，不能上传 GitHub，也不要通过聊天发送给同学。

### 密码填写位置

首次运行如果脚本提示缺少密码，不要把密码填到根目录 `.env`，也不要把密码发到聊天或提交到 GitHub。分别编辑对应文件：

```powershell
notepad .\services\OpenMes\.env
notepad .\services\frappe_docker\.env
```

填写或修改以下字段（等号后填自己的本机密码，不要保留空值）：

| 文件 | 字段 | 用途 |
| --- | --- | --- |
| `services/OpenMes/.env` | `ADMIN_USERNAME`、`ADMIN_PASSWORD` | OpenMES 管理员登录 |
| `services/frappe_docker/.env` | `DB_PASSWORD` | ERPNext 数据库 root 密码 |

保存并关闭记事本后，回到正在等待的脚本窗口按 Enter 继续。如果脚本已经回到 `PS ...>` 提示符，说明本轮已结束，应重新运行入口命令，不能只继续按 Enter。

## 首次运行的人工步骤

### 1. 填写 OpenMES 本机配置

编辑 `services/OpenMes/.env`，至少设置上游模板要求的管理员账号和密码（通常是 `ADMIN_USERNAME`、`ADMIN_PASSWORD`）。密码由使用者自行设置，脚本不会读取后打印，也不会把密码写入本仓库。

### 2. 启动外部系统

引导脚本会调用已有的 `scripts/deploy_services.ps1`，以两个独立 compose project 启动：

- OpenMES：默认 `http://127.0.0.1/`；
- ERPNext：默认 `http://127.0.0.1:8080/`。

首次拉取镜像可能需要较长时间，ERPNext 镜像尤其可能长时间显示 `Pulling`，这是首次下载和解压镜像层的过程。只要进度或日志仍在变化，就等待它完成。脚本会等待 `/api/health` 和 ERPNext ping 接口；任一服务未就绪都不会继续写种子。

如果拉取结束时出现 `unexpected EOF`，先不要改配置，单独重试目标镜像，然后重新运行入口脚本：

```powershell
docker pull frappe/erpnext:v16.36.0
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1
```

如果 Docker Desktop 弹出 `containerd`、`SIGBUS`、`bus error` 或 `core dumped`，这不是正常的下载提示：先退出并重新打开 Docker Desktop，确认 `docker version` 同时显示 `Client` 和 `Server` 后再重试。不要直接点击“恢复出厂设置”；它可能删除本机容器、镜像和卷。

### 3. 完成 ERPNext localhost 建站

引导脚本会用容器内 `bench --site localhost list-apps` 检查站点。如果站点不存在，它会打印一次性建站命令。需要使用者把 `services/frappe_docker/.env` 中的 `DB_PASSWORD` 和自己设置的 ERPNext 管理员密码填入命令中的占位符；不要把真实密码复制到文档或提交记录。

站点创建完成并安装 `erpnext` 后，重新运行引导脚本，或在提示处确认后继续。

### 4. 创建本机专用 ERPNext API 凭据

在 ERPNext 中创建一个供本项目读取/草稿写入的专用用户，生成 API Key/Secret，填写根目录 `.env`：

```dotenv
APP_ADAPTER_MODE=real
ERPNEXT_BASE_URL=http://127.0.0.1:8080
ERPNEXT_API_KEY=<本机 ERPNext 专用用户的 key>
ERPNEXT_API_SECRET=<本机 ERPNext 专用用户的 secret>
REAL_WRITE_API_TOKEN=<本机自行生成的随机字符串>
```

不要使用或复制项目作者电脑上的 key/secret。`REAL_WRITE_API_TOKEN` 只是本机写入门禁令牌，也必须每台电脑单独设置。

### 5. 配置 OpenMES 会话与 ERP 集成 Key

OpenMES 管理员账号可登录后，按现有项目脚本完成本机 Token/API Key 配置：

```powershell
python backend\get_openmes_token.py
```

该脚本只把当前本机短时会话和集成 Key 写入本机 `.env`，不会上传；Token 有效期和刷新规则以 OpenMES 当前部署为准。若 OpenMES 上游版本的字段或接口与现有脚本不一致，应先停下并核对上游文档，不能猜字段名或接口行为。

### 6. 可选的协同问答模型 Key

如需使用真实 DeepSeek 问答，在 `.env` 填入使用者自己的 `DEEPSEEK_API_KEY`。不填时，页面会明确显示未配置，不能把作者的 Key 复制给同学。

## 演示数据种子顺序与重复运行风险

引导脚本默认不自动写业务数据。确认外部系统和凭据都健康后，可运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1 -RunSeeds -RunRealDemoSeed
```

脚本使用以下顺序；每一步失败都会停止，不会静默跳过：

| 顺序 | 脚本 | 写入范围 | 重复运行结论 |
| --- | --- | --- | --- |
| 1 | `backend/seed_erpnext.py` | UOM、公司、客户、供应商、物料、BOM、价格 | `create()` 遇到失败会打印 SKIP，整体接近幂等；需人工检查 HTTP 错误，不能把“SKIP”当成全部成功 |
| 2 | `backend/seed_openmes.py` | OpenMES 产品、工单导入、质量问题与只读集成验证 | 产品/工单导入声明 `update_or_create`；质量问题使用 POST，重复运行可能新增重复问题，属于“部分可重跑” |
| 3 | `backend/seed_supplier_data.py` | ERPNext 物料交期、最小采购量、供应商关系和供应商价 | 脚本有查重/跳过逻辑，可重跑；仍应查看回读结果 |
| 4 | `backend/seed_real_demo.py` | 动态查询产品类型、产线、问题类型；按 `TEST_` 工单号和问题描述查重后导入 3 条演示工单及 1 条质量问题 | 推荐的跨机器 OpenMES 演示数据入口；缺少主数据时明确停止，不猜测创建方式 |
| 5（默认跳过） | `backend/seed_inspection_eta.py` | `TEST_` 检验记录和 `TEST_` 批次时间；直接写 OpenMES 数据库 | 虽然固定值查重可重跑，但依赖容器名 `openmes-postgres`、`TEST_WO_PAGE_00023`/`TEST_LOT_PAGE_9` 和当前表结构；干净数据库通常没有这些前置数据，不能当通用导入 |
| 6（默认跳过） | `backend/seed_openmes_v2.py` | 通过用户 API 新建工单和质量问题 | **非幂等**：会 POST 新工单/问题，重复执行会产生重复业务记录 |
| 7（默认跳过） | `backend/seed_openmes_v3.py` | 接受/启动固定工单，并新建质量问题 | **非幂等且依赖固定 ID**：会使用工单 id=2/3/4、Issue Type id=7/2；换一台数据库后这些 ID 可能不存在或指向别的记录 |

确实需要第 5、6 步时，必须先备份 OpenMES 数据，并显式运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1 -RunSeeds -RunLegacySeeds
```

脚本会再次警告并要求输入 `RUN`。不要在没有核对工单 ID、Issue Type 和当前库状态时运行；这些值来自当前项目的真实环境，换一台机器后可能不同。若脚本或上游 API 返回未知字段/状态，应停止并提供资料，不要自行猜测。

`seed_inspection_eta.py` 另有独立开关，不能和“基础种子”混为一谈：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1 -RunSeeds -RunEtaSeed
```

运行前必须先确认 `openmes-postgres` 容器、`TEST_WO_PAGE_00023`/`TEST_LOT_PAGE_9` 和所需表结构都存在；脚本只会提示并要求确认，不会替使用者猜测或创建这些未知前置数据。

`seed_real_demo.py` 是给新机器使用的通用 TEST_ 数据入口；它不会创建产线、产品类型或问题类型，因为当前仓库没有确认这些资源在所有 OpenMES 版本上的统一创建契约。若运行它时提示缺少主数据，应先按当前 OpenMES 版本的管理界面/API完成主数据准备，再重新运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_real_environment.ps1 -RunSeeds -RunRealDemoSeed
```

## 启动业务应用

外部系统和种子完成后运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1
```

这里的脚本名称沿用项目历史命名；在 `APP_ADAPTER_MODE=real` 下，页面只显示真实 ERPNext/OpenMES 返回的数据，连不上时应报错，不会把 Mock 结果当成真实结果。入口为 `http://127.0.0.1:5173/`。

## 验收清单

同学电脑只有完成以下清单，才算“与当前真实环境一致”：

- [ ] Docker Desktop 正常，`docker compose ps` 中两个独立项目均已启动。
- [ ] OpenMES `/api/health` 和 ERPNext `api/method/ping` 均响应。
- [ ] ERPNext `localhost` 站点可登录，项目专用 API Key/Secret 在本机 `.env` 中有效。
- [ ] OpenMES 管理员登录有效，根目录 `.env` 中的本机 Token/API Key 验证通过。
- [ ] `alembic upgrade head` 完成，后端 `/api/health`、真实业务表面和集成状态返回正常。
- [ ] 运行安全种子后，ERPNext 物料/客户/供应商/价格与 OpenMES 产品/工单/检验数据可回读。
- [ ] 前端能打开业务总览、AI 协同问答、销售/采购/生产/质量页面。
- [ ] 至少完成一次自然语言查询，并能在页面看到对应真实工单/质量/交期数据。
- [ ] 重启 Docker 和应用后再次验收，数据仍存在且没有静默切回 Mock。
- [ ] 在一台没有项目依赖的干净 Windows 电脑上，从 GitHub 克隆后完整复现，并记录耗时、镜像版本、失败点和修复方式。

## 给同学的最小交付内容

提交 GitHub 前只提交源代码、脚本、模板和本文件。不要提交：

- 根目录 `.env`、`frontend/.env.local`、`services/*/.env`；
- ERPNext API Secret、OpenMES Token/API Key、DeepSeek Key、Cookie、证书、私钥；
- `services/` 下的上游源码副本或数据库卷；
- 包含密钥的终端截图和日志。

同学拿到仓库后，每人都按本文生成自己的外部系统、账号、密钥和数据。大家看到的是相同的系统结构和种子脚本定义，但不是共享同一份实时数据库。

## 当前风险和未完成项

1. 上游 OpenMES/ERPNext 版本、镜像和接口可能变化；本脚本没有把未知 API 字段写死为新的假设。
2. 引导脚本调用现有 compose 与种子脚本，未在一台全新 Windows 电脑上完成完整实测；完成前不要在比赛材料中写“任何电脑一键部署”。
3. ERPNext 建站、专用用户/API Key、OpenMES 管理员和 Token 仍需人工完成；自动填入密码会增加泄露风险，因此脚本只提示，不收集和打印密码。
4. 非幂等种子必须人工确认；如果需要真正做到可重复初始化，应先为这些脚本增加按稳定业务编号查重或提供可回滚的数据库快照，再把它们加入默认流程。
5. 如果比赛要求通过梧桐平台发现/调用智能体，还需要单独完成 ACS 注册、证书和可访问地址配置；本地 `localhost` RPC 地址不能直接作为同学电脑或平台的公共服务地址。

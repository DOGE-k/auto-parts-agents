> 本文面向项目维护者和后续开发者。第一次使用项目请先看根目录 [`README.md`](../README.md)；第一次部署请看 [`真实环境复现部署.md`](真实环境复现部署.md)。

## 本地开发入口

### 后端

```powershell
cd backend
python -m pip install -e .
python -m pytest tests -q
python -m compileall -q app
```

### 前端

```powershell
cd frontend
npm install
npm run test -- --run
npx tsc --noEmit --incremental false --project tsconfig.json
npm run build
```

### 真实环境启动

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1
```

真实环境部署和凭据填写方式不要从历史交接文档里猜，统一以 [`真实环境复现部署.md`](真实环境复现部署.md) 为准。

## 修改时必须保持的边界

- 不把密码、Token、API Secret、Cookie 或数据库文件提交到 Git；
- 不把 `TEST_` / `DEMO_` 演示数据写成真实工厂生产数据；
- 不为 OpenMES 或 ERPNext 猜测不存在的字段、接口和业务规则；
- 新增真实系统写入时，必须同时设计人工审批、回写、回读验证和幂等；
- 真实适配器、Mock、fixture 和前端展示数据要保持隔离；
- 如果真实接口没有能力，页面应显示缺失或不支持，不能用固定值补齐；
- 改动功能后同步更新用户可见文档和演示验收路径。

## 提交前检查

1. `git diff` 只包含本次任务需要的文件；
2. 根目录 `.env`、`services/`、前端依赖和运行日志没有进入提交；
3. 后端测试、前端测试、类型检查和构建按本次改动范围执行；
4. 如果改了真实接口适配器，补充 HTTP 状态码、来源、回读和失败边界；
5. 如果改了页面流程，更新 [`功能介绍.md`](功能介绍.md) 和 [`demo_runbook.md`](demo_runbook.md)；
6. 只把已验证的结果写成“已完成”，其余写成“待验证”或“当前限制”。

## 文档分层规则

- 面向同学和老师的内容放在 README、`项目说明.md`、`真实环境复现部署.md`、`功能介绍.md` 和 `demo_runbook.md`；
- 面向开发者的实现背景放在本文、`AI_HANDOFF_PLAN.md` 和当前交接文档；
- 已过期的计划和历史证据放在 `obsolete/` 或保留在状态记录中，不放进新手推荐路线；
- 每份文档开头写清楚读者、用途、验证时间和不能据此推断的内容。
